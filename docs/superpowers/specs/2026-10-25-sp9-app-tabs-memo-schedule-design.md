## 1. 목표와 완료 조건

Dahun은 앱 하나로 하루를 굴린다. 아래 탭에서 **오늘 / 할 일 / 스케줄 / 메모**로 바로 가고, 설정·기록·습관은 필요할 때만 꺼낸다. 시간이 정해진 일은 스케줄에 넣고 그 시간 전에 앱 푸시를 받는다. 떠오른 것은 메모에 적는다. 채팅은 대화별로 나뉘어 목록으로 다시 찾을 수 있고, 비서는 지난 대화 원문을 매번 읽지 않는다.

**완료 조건 (수용 기준)**

1. 앱 아래 탭 막대가 `오늘 | 할 일 | 스케줄 | 메모` 네 칸이다. 네 탭 모두 큰 제목 오른쪽에 같은 원형 아이콘이 있고, 누르면 `/more/` 화면에 설정, 기록, 습관, 상태창(SP8 머지 뒤), 기기 연결 줄이 보인다. 각 화면의 돌아가기는 "‹ 더보기"다.
2. 스케줄 탭에서 "내일 14:00 치과, 30분 전 알림"을 만들면 위 한 주 띠의 내일 칸에 점이 찍히고, 내일 13:30에 앱 푸시 "치과 · 14:00 (30분 뒤)"가 온다. 알림을 고르지 않으면 10분 전이다.
3. 노트북이 13:20~13:45 동안 꺼져 있었다면, 켜진 직후 "치과 · 14:00 (15분 남았어요)" 푸시가 한 번 온다. 14:10까지 꺼져 있었다면 푸시는 없고 오늘 화면에 "놓친 알림: 치과 · 14:00" 줄이 보인다.
4. "매주 월 10:00 팀 회의"를 만들면 다음 월요일마다 보이고, 한 날을 "이번만 건너뛰기"하면 그날만 빠진다. "이후 반복 끝내기"를 하면 그날부터 사라진다.
5. 설정의 "아이폰 캘린더에 구독" 주소를 아이폰 캘린더에 넣으면 스케줄이 읽기 전용으로 보인다(폰 Tailscale 켜짐, 노트북 켜짐일 때 갱신).
6. 메모 탭에서 "+"를 누르고 "읽을 책\n- [ ] 사피엔스"를 적으면 목록에 제목 "읽을 책"으로 보이고, 보기 화면에서 체크박스를 누르면 `- [x]`로 저장된다. 검색창에 "사피"를 치면 그 메모가 나온다. 고정한 메모는 위에 있다.
7. 채팅에서 "지난번에 적은 책 이름 뭐였지?"라고 하면 두뇌가 `search_memos`로 찾아 답한다. "이거 메모해줘"라고 하면 메모가 생기고 "✓ 메모를 만들었어요: {제목}" 한 줄이 붙는다. 두뇌는 메모를 고치거나 지울 수 없다(도구가 없다).
8. 채팅 시트 왼쪽 위 목록 버튼에서 앱 대화들이 날짜별로, 비서가 붙인 제목과 함께 보인다. 대화를 열어 읽고, 검색하고, 지울 수 있다. 지난 대화를 열어 말하면 그 대화가 이어진다. "새 대화"를 누르면 열린 대화가 닫히고 빈 대화가 시작된다.
9. 새 대화의 첫 두뇌 호출 입력에는 다른 대화의 원문이 없다(앞머리와 공유 상태만, 테스트로 확인). 두뇌가 지난 대화가 필요하면 `find_conversations`로 요약만 읽는다.
10. 한 대화의 사용자 메시지가 30개를 넘으면 다음 호출부터 새 두뇌 세션이 그 대화의 요약과 최근 6줄로 시작한다(말아 넣기). 화면의 대화는 하나로 그대로 보인다.
11. 채팅 입력창 위에 퀵 칩 줄이 있다. 고정 칩 4개(할 일 추가, 일정 추가, 메모하기, 오늘 정리해줘)와, 때에 맞는 칩 1개(체크인 하기 / 이번 주 돌아보기 / 다음 일정 보기)가 맨 앞에 붙는다. 칩을 누르면 정해진 문장이 내 말풍선으로 보내진다.
12. 비서가 무언가를 바꾸면 채팅에는 "✓ 할 일 3개를 내일로 옮겼어요" 한 줄만 남고 회색 상자와 되돌리기 버튼이 없다. 같은 때 토스트에 "되돌리기"가 6초 동안 보인다. 그 뒤에는 더보기 → 기록에서 되돌린다.
13. 설정의 "체크인 시간"에서 평일 아침을 09:30으로 바꾸면 노트북 재시작 없이 다음 아침 브리핑이 09:30에 온다. 채팅에서 "저녁 체크인 6시로 바꿔줘"라고 하면 확인 카드가 뜨고, 확인해야 바뀐다.
14. 12장의 자동 테스트가 모두 통과한다. 새 문구에도 금지어 검사(SP5 10장)가 돈다.

## 4. 접근안과 선택

### 4.1 스케줄을 어디에 두나 (ADR 0015)

| 안 | 내용 | 판단 |
|---|---|---|
| A. 할 일의 `scheduled_at`을 키운다 | 지금처럼 할 일에 시각을 붙이고 반복·알림 칸을 더한다 | **버림**. 할 일은 "끝낸다"가 있고 스케줄은 없다. 반복을 할 일로 만들면 SP7이 버린 "밀린 일 쌓임"이 그대로 생긴다(ADR 0011). 우선순위·초안·첫 걸음 규칙도 일정에는 맞지 않는다 |
| B. `events` 표와 건너뛴 날 표 (선택) | 정의 한 행에 반복 규칙을 담고, 그날 일정은 읽을 때 펼친다. 건너뛴 날만 따로 남긴다 | **선택**. 끝내기·밀림이 없다. 그날 일정을 미리 만들지 않으니 "이후 반복 끝내기"가 한 칸 바꾸기다 |
| C. 그날 일정을 미리 행으로 만든다 | 반복 일정의 앞으로 N주 그날 일정을 행으로 만든다 | 버림. 반복을 바꿀 때 만든 행을 고치고 지워야 하고, 기간 밖은 비어 보인다 |

### 4.2 대화 세션 (ADR 0014)

| 안 | 내용 | 판단 |
|---|---|---|
| A. 대화마다 독립 세션 + 요약 (선택) | 대화 하나 = 두뇌 세션 하나. 새 세션은 앞머리(공유 상태)로만 시작한다. 닫힐 때 요약을 남기고, 필요하면 도구로 꺼낸다 | **선택**(Q10). 컨텍스트가 대화 수와 상관없이 일정하다. 서브에이전트도 같은 모양으로 붙일 수 있다 |
| B. 요약 없이 완전 분리 | 지난 대화는 두뇌가 모른다 | 버림. "어제 얘기한 거"가 안 된다 |
| C. 최근 요약 3개를 늘 넣기 | 새 세션 앞머리에 최근 요약을 붙인다 | 버림. 쓰지 않는 컨텍스트가 매번 든다 |

지금도 대화마다 `conversations.session_id`가 있고 새 대화는 앞머리로 새 세션을 연다(SP1 5.3). 이번에 더하는 것은 요약, 목록, 지우기, 잇기, 말아 넣기다.

## 5. BE: 스케줄

### 5.1 `016_events.sql`

```sql
-- 016: 스케줄 (SP9 스펙 5.1, ADR 0015). 시각은 UTC ISO 8601, 날짜는 현지 날짜 YYYY-MM-DD(논리적 날짜가 아니다).
CREATE TABLE events (
    id              INTEGER PRIMARY KEY,
    title           TEXT NOT NULL CHECK (length(title) BETWEEN 1 AND 100),
    all_day         INTEGER NOT NULL DEFAULT 0 CHECK (all_day IN (0, 1)),
    start_date      TEXT NOT NULL,              -- 첫 날의 현지 날짜
    start_time      TEXT NULL,                  -- 현지 "HH:MM". all_day = 1이면 NULL
    duration_min    INTEGER NULL CHECK (duration_min BETWEEN 5 AND 1440),
    repeat          TEXT NOT NULL DEFAULT 'none' CHECK (repeat IN ('none', 'daily', 'weekly', 'monthly')),
    weekdays        INTEGER NULL CHECK (weekdays BETWEEN 1 AND 127),  -- weekly만. 월=1, 화=2, … 일=64
    repeat_until    TEXT NULL,                  -- 마지막 날이 될 수 있는 현지 날짜(포함). NULL = 끝없음
    remind_min      INTEGER NULL CHECK (remind_min IN (0, 10, 30, 60, 1440)),  -- NULL = 알림 없음
    area            TEXT NULL CHECK (area IN
        ('career', 'finance', 'health', 'relationships', 'learning', 'quality_of_life')),
    note            TEXT NOT NULL DEFAULT '' CHECK (length(note) <= 1000),
    origin          TEXT NOT NULL CHECK (origin IN ('user', 'chat', 'migrated')),
    from_task_id    INTEGER NULL REFERENCES tasks (id),
    created_at      TEXT NOT NULL,
    updated_at      TEXT NOT NULL,
    deleted_at      TEXT NULL,
    CHECK ((all_day = 1) = (start_time IS NULL)),
    CHECK ((repeat = 'weekly') = (weekdays IS NOT NULL)),
    CHECK (repeat <> 'none' OR repeat_until IS NULL)
);

CREATE INDEX idx_events_live ON events (deleted_at, start_date);

CREATE TABLE event_skips (
    event_id        INTEGER NOT NULL REFERENCES events (id),
    occurrence_date TEXT NOT NULL,
    created_at      TEXT NOT NULL,
    PRIMARY KEY (event_id, occurrence_date)
);

-- 알림을 보냈거나 놓쳤다고 판정한 그날 일정. 같은 날에 두 번 보내지 않는다.
CREATE TABLE event_reminders (
    event_id        INTEGER NOT NULL REFERENCES events (id),
    occurrence_date TEXT NOT NULL,
    remind_at       TEXT NOT NULL,              -- UTC
    outcome         TEXT NOT NULL CHECK (outcome IN ('sent', 'late_sent', 'missed', 'failed')),
    decided_at      TEXT NOT NULL,
    dismissed_at    TEXT NULL,                  -- 오늘 화면에서 "놓친 알림" 줄을 닫았다
    PRIMARY KEY (event_id, occurrence_date)
);
```

- 시각을 UTC가 아니라 **현지 날짜 + "HH:MM"** 으로 두는 이유: 반복 일정의 날짜는 현지 벽시계 기준이다. 시간대는 `settings.timezone` 하나(Asia/Seoul, 서머타임 없음)라 그날 일정의 UTC는 `local(date, time) → UTC`로 바로 나온다.
- 하루 종일 일정의 알림 기준 시각은 그날 **09:00**(현지)이다. `remind_min = 0`이면 그날 09:00, `1440`이면 전날 09:00. 10·30·60분은 하루 종일 일정에서 고를 수 없다(API 422 `remind_invalid`).
- 매달 반복의 날짜가 없는 달(31일, 2월 29·30일)은 **그 달의 마지막 날**로 옮긴다. 예: 1월 31일 시작 → 2월 28일(2027) → 3월 31일.
- 상한: 살아 있는 일정 300개(넘으면 422 `too_many_events`).

### 5.2 저장소 `store/repos/events.py`

- `EventsRepo.create(...) / update(id, fields) / delete(id)`(지우기는 `deleted_at`), `skip(id, date)`, `unskip(id, date)`, `end_repeat(id, from_date)`(`repeat_until = from_date - 1일`, `from_date`가 첫 날이면 지우기와 같다).
- `occurrences(start_date, end_date) -> list[Occurrence]`: 기간(포함, 최대 62일) 안의 그날 일정을 시작 시각순으로. `Occurrence(event_id, date, start_utc | None, end_utc | None, all_day, title, area, remind_at_utc | None, skipped=False)`. 건너뛴 날은 빼고 준다(`include_skipped=True`일 때만 넣는다, 되돌리기용).
- 펼치기는 순수 함수 `expand(event, start, end)`로 둔다(테스트하기 쉽게, `loop/schedule.py`와 같은 방식).

### 5.3 알림 (1분 tick)

`loop/runner.py`의 1분 tick에 `remind_events(prev_tick, now)`를 더한다. 두뇌를 부르지 않는다.

| 경우 | 판정 | 하는 일 |
|---|---|---|
| R1 | `remind_at ∈ (prev_tick, now]`이고 공백이 3분 미만(`RESUME_GAP`) | 주 통로로 보낸다. `outcome = sent` |
| R2 | 공백이 3분 이상(절전·꺼짐에서 깨어남)이고 `remind_at`이 공백 안, 그날 일정 시작 시각 > now | 바로 보낸다, 본문에 남은 시간("15분 남았어요"). `outcome = late_sent` |
| R3 | R2와 같은데 그날 일정 시작 시각 ≤ now (하루 종일 일정은 그날이 지났을 때) | 보내지 않는다. `outcome = missed`. 오늘 화면 "놓친 알림"에 보인다 |
| R4 | 보내기 실패(구독 없음, 410 등) | 기존 주 통로 규칙대로 텔레그램 대체(SP3-4 7.3 D1a). 그것도 안 되면 `outcome = failed`, 오늘 화면에 R3처럼 보인다 |

- 공백 판정은 tick의 `prev_tick`(하트비트)으로 한다. 공백이 24시간을 넘어도 같은 규칙이고, 한 번에 보내는 늦은 알림은 **최대 3개**(가장 가까운 시작 순). 나머지는 `missed`로 남긴다.
- 알림은 비서가 먼저 보내는 메시지 상한(`daily_proactive_messages = 3`)에 **세지 않는다**. 사용자가 시각을 정한 알림이라서다. 대신 하루 알림 상한 `limits.daily_event_reminders = 30`을 둔다.
- 일정을 만들거나 바꿀 때 이미 지난 `remind_at`(예: 10분 뒤 시작, 30분 전 알림)은 보내지 않고 기록도 남기지 않는다.
- 일정의 시각·알림을 바꾸면 그 일정의 **앞으로의** `event_reminders` 행(아직 시작 전인 날)을 지운다. 새 시각으로 다시 판정한다.
- 푸시 본문: 제목 `{title}`, 본문 `{HH:MM} ({남은 말})`. 남은 말: 정시 "지금이에요", 10/30/60분 "{n}분 뒤", 하루 전 "내일", 늦게 보냄 "{n}분 남았어요", 하루 종일 "오늘" 또는 "내일". 누르면 앱 `/schedule/?date=YYYY-MM-DD`.
- 텔레그램 대체 문구는 같은 한 줄이다(새 명령·버튼 없음).

### 5.4 할 일의 시각을 스케줄로 옮기기 (마이그레이션 016 안)

- `status = 'open'`이고 `scheduled_at IS NOT NULL`이고 `deleted_at IS NULL`인 할 일마다 `events` 한 행을 만든다: 제목, 영역(첫 영역), `note`, 한 번짜리, `remind_min = 10`, `origin = 'migrated'`, `from_task_id`. 그 할 일은 `deleted_at`을 채우고 `task_events(kind = 'updated', payload = {"moved_to_event": <id>})`를 남긴다.
- 끝냈거나 버린 할 일의 `scheduled_at`은 그대로 둔다(기록).
- 마이그레이션은 DB 백업 뒤에 돈다(SP6 updater 규칙 그대로). 옮긴 개수는 로그에 숫자만 남긴다.
- 이후 `create_task`·`update_task`는 `scheduled_at`을 받지 않는다. 두뇌가 넘기면 도구 결과: "시간이 정해진 일은 스케줄로 만들어요. create_event를 써 주세요." 앱의 할 일 추가·고치기 시트에서 시각 칸을 뺀다. `confirmations.py`의 "timed 할 일 날짜 옮기기" 확인은 `update_event` 확인으로 옮긴다.

### 5.7 아이폰 캘린더 구독 주소

- `GET /api/v1/calendar.ics?key=<캘린더 키>`: iCalendar(RFC 5545). 일정마다 `VEVENT` 하나, 반복은 `RRULE`(`FREQ=DAILY|WEEKLY;BYDAY=…|MONTHLY;BYMONTHDAY=…`, `UNTIL`), 건너뛴 날은 `EXDATE`. 매달 29~31일 반복은 `RRULE`이 그 날짜가 없는 달을 건너뛰므로, 그런 달의 마지막 날(5.1 규칙)을 앞으로 12개월치 `RDATE`로 더한다. `VALARM`은 넣지 않는다(알림은 앱이 한다. 겹쳐 울리지 않게).
- 캘린더 키: API 토큰과 **다른** 32바이트 무작위 키. 이 경로만 열고 읽기만 된다. `app_state.calendar_key`에 해시로 둔다. 설정 화면에서 만들기·다시 만들기(이전 주소는 바로 끊김).
- 아이폰 캘린더는 머리글을 못 보내므로 주소에 키가 들어간다. 그래서 키는 이 경로 하나에만 쓰고, 접근 로그에서 `key=` 값을 가린다.
- 테일넷 안 주소라서 폰에서 Tailscale이 켜져 있어야 갱신된다. 설정 화면에 그 한 줄을 적는다.

### 6.2 서식

- 쓰는 것: 첫 줄 제목, 목록 `- `, 번호 목록 `1. `, 체크박스 `- [ ]`/`- [x]`, 굵게 `**`. 그 밖의 마크다운은 글자 그대로 보인다.
- 앱 렌더러는 SP6의 `markdown-to-jsx` 설정을 쓰고, 메모에서는 체크박스를 누를 수 있게 한다(누르면 그 줄의 `[ ]`↔`[x]`를 바꿔 `update_memo`로 저장).

### 7.2 요약 만들기

- **언제**: 대화가 닫힐 때(30분 규칙, 계획 2시간 만료, "새 대화", 다른 대화 열기)와 말아 넣기(7.4) 직전. 닫힌 대화를 다음 tick에서 큐에 넣고 순서대로 한다.
- **어떻게**: 두뇌 호출 한 번, **도구 없음**, `max_turns = 1`. 입력은 그 대화의 원문 줄(`redact()` 거침, `input_max_chars`까지 뒤에서부터) + 이전 요약(있으면). 출력은 JSON `{"title": "…(20자 이하)", "summary": "…(600자 이하)"}`. 프롬프트 `prompts/summarize.md`(새 파일): 결정, 만든·바꾼 것, 다음에 할 것 위주. 인증·식별 정보는 쓰지 않는다.
- **비용**: 하루 두뇌 호출 상한(`daily_brain_calls`)에 센다. 대신 요약은 따로 `limits.daily_summaries = 15`를 넘지 않는다. 상한이나 두뇌 오류면 제목은 첫 사용자 메시지 앞 20자, 요약은 비워 두고 하루 한 번 작업에서 다시 해 본다.
- 사용자 메시지가 1개 이하이고 비서 답이 짧은(200자 미만) 대화는 두뇌를 부르지 않고 첫 메시지로 제목만 정한다.
- 이번 대상은 **앱 통로**의 `chat`, `plan`, `run` 대화다. 텔레그램 대화는 요약하지 않는다(Q14).

### 7.3 지난 대화 잇기와 새 대화

- `POST /chat` 본문에 `conversation_id`(선택)를 더한다. 주면 그 대화로 보낸다:
  - 그 대화가 앱 통로이고 지우지 않았으면, 열린 다른 앱 `chat`·`plan` 대화를 닫고(요약 큐로) 그 대화를 다시 연다(`closed_at = NULL`, `last_message_at = now`).
  - 두뇌는 그 대화의 `session_id`로 `resume`한다. resume이 실패하면(세션 파일 없음, SP1 5.3) 새 세션을 앞머리 + `## 이 대화의 지난 내용`(요약) + 최근 6줄로 시작한다.
  - `run` 대화(체크인)는 답장 창이 지났으면 `chat` 대화로 새로 열고 그 회차 대화의 요약을 앞에 붙인다(회차 규칙을 깨지 않는다).
- `POST /conversations/new`: 열린 앱 `chat`·`plan` 대화를 닫는다. 다음 메시지는 새 대화가 된다. 응답 `{ "closed": [id…] }`.
- 30분 규칙은 그대로다. 목록에서 대화를 고르지 않고 보내면 지금처럼 정한다.

### 7.4 말아 넣기 (긴 대화 자동 압축)

- 한 대화의 `user_messages`가 30을 넘으면, 그다음 사용자 메시지 전에 요약(7.2)을 갱신하고 `session_id`를 비운다. 다음 호출은 새 세션: 앞머리 + `## 이 대화의 지난 내용`(요약) + 최근 6줄 + 이번 메시지. `user_messages`는 다시 0부터 센다.
- Agent SDK(CLI)의 자체 자동 압축은 그대로 둔다. 말아 넣기는 그보다 먼저, 예측 가능한 지점에서 일어나게 하는 장치다.
- 화면에서는 같은 대화 하나로 보인다. 말아 넣은 자리에 구분선이나 문구를 보이지 않는다.

### 7.5 `find_conversations` 도구 (앱 대화에만)

- `find_conversations(query?, days=14, limit=5)`: 앱 통로의 닫힌 대화 중 `query`가 제목·요약에 맞는 것(없으면 최근 것). 결과는 `id, 날짜, 제목, 요약`. **원문은 주지 않는다.**
- 프롬프트 규칙: "사용자가 지난 대화를 언급하거나 앞머리·도구로 알 수 없는 맥락이 필요할 때만 쓴다."

### 7.6 HTTP API

| 경로 | 내용 |
|---|---|
| `GET /conversations?channel=app&q=&before=&limit=` | 기존 경로에 `title`, `summary`(앞 120자), `q`(제목·요약 검색), `before`(쪽 넘기기) 추가. 지운 대화는 빼고 준다 |
| `GET /conversations/{id}/messages` | 그대로. 지운 대화는 404 |
| `DELETE /conversations/{id}` | 대화 지우기(7.7). 열린 대화를 지우면 먼저 닫는다 |
| `POST /conversations/new` | 7.3 |

### 7.7 대화 지우기

- `deleted_at`을 채우고 `title`, `summary`를 비운다. 목록·검색·`find_conversations`·`/messages`에서 사라진다.
- 원문 기록(`data/transcripts/…md`)에서 그 대화의 줄을 `[지운 대화]` 한 줄로 바꿔 다시 쓴다. 원문 기록은 덧붙이기만 한다는 규칙(SP1 5.8)의 유일한 예외로 적는다. 그날 파일을 임시 파일에 쓰고 바꿔 넣는다(Windows에서 `os.replace`).
- 두뇌 세션 파일은 SDK 저장 위치에서 그 `session_id` 파일을 지운다(없으면 넘어간다).
- 되돌릴 수 없다. 앱은 확인 시트 "이 대화를 지울까요? 되돌릴 수 없어요."를 거친다. 활동 기록에는 "대화를 지웠어요"만 남는다(되돌리기 없음).

## 8. BE: 체크인 시간 바꾸기

- `app_state.schedule_override`(JSON): `{"morning_brief": {"weekday": "09:30", "weekend": "10:00"}, "evening_checkin": {…}}`. 칸이 없으면 `config.toml` 값. `loop/schedule.py`는 `effective_schedule(settings, overrides)`를 받아 쓴다(순수 함수 유지).
- 허용 범위: 아침 05:00~11:30(아침 답장 창 12:00보다 30분 앞), 저녁 15:00~23:30. 10분 단위. 벗어나면 422 `checkin_time_invalid`.
- 주간 회고 시각(`schedule.review.week`)은 **주말 저녁 체크인 시각을 따라간다**(일요일 저녁에 합친 결정, SP1). 바꾸면 회고도 같은 시각이다.
- **적용 시점**: 오늘 그 루프의 회차가 이미 만들어졌으면 오늘은 그대로, 내일부터 새 시각. 아직 안 만들어졌으면 새 시각이 지금 뒤일 때만 오늘부터, 지금 앞이면 오늘은 원래 시각(아직 안 지났으면 그대로 온다, 지났으면 이미 만들어졌을 것)으로 두고 내일부터. 시각을 바꿔서 따라잡기 회차가 생기는 일은 없다.
- API: `GET /settings/checkin-times`, `PUT /settings/checkin-times`(네 칸 중 바꿀 칸만). 응답에 지금 적용되는 네 값과 "오늘부터/내일부터"를 준다.
- 두뇌 도구 `set_checkin_time(loop, day_type, time)`(앱 대화에만): 언제나 `needs_confirm` "체크인 시간을 바꿔요: 평일 아침 09:00 → 09:30 (내일부터)". 되돌리기 있음(이전 값으로).

## 9. 운영 앱

### 9.1 탭 막대와 더보기

- `TabBar.tsx`의 칸: `today "/"`, `todos "/todos/"`, `schedule "/schedule/"`, `memos "/memos/"`. 문구 `오늘`, `할 일`, `스케줄`, `메모`.
- 새 아이콘 3개(`schedule`, `memo`, `more`)는 `icons.tsx`에 그린다. SP8 픽토그램 규칙(24px, 선 1.75, 끝 둥글게, 이모지 없음)에 맞춘다. SP8이 공용 스프라이트를 만들 때 옮겨 담는다(SP8 스레드와 합의).
- `LargeTitle`에 오른쪽 자리(`trailing`)를 더하고 네 탭 모두 원형 32px 버튼(아이콘 `more`, `aria-label="더보기"`)을 둔다. 누르면 `/more/`.
- `/more/` 화면(탭 밖, 큰 제목 "더보기", 돌아가기 없음. 탭 막대는 보인다): iOS 묶음 목록 한 덩어리에 `설정`, `기록`, `습관`, `상태창`(SP8 머지 뒤), `기기 연결`. 각 화면(`/settings/`, `/activity/`, `/habits/`, `/status/`, `/connect/`)의 돌아가기는 "‹ 더보기". 이 화면들에서는 탭 막대의 어느 칸도 선택 표시를 하지 않는다.
- 기존 주소는 그대로라 바로가기·푸시 링크가 깨지지 않는다.

### 9.2 스케줄 탭 (`/schedule/`)

- 큰 제목은 보고 있는 달("10월"). 누르면 그 아래 한 달 달력이 펼쳐진다(다시 누르면 접힘). 달력의 날을 누르면 그 주로 가고 접힌다.
- 한 주 띠: 월~일 7칸, 오늘은 잉크 원, 고른 날은 테두리, 일정이 있는 날은 아래 점 하나(개수 표시 없음). 좌우로 밀면 앞뒤 주. 처음엔 오늘.
- 그날 목록: 하루 종일 일정 먼저, 그다음 시각순. 줄 = 시각("14:00", 하루 종일은 "하루 종일"), 제목, 영역 점(DESIGN.md: 영역색은 작은 점으로만), 반복이면 작은 반복 표시, 비서가 만든 것은 SP6 규칙대로 파란 "비서" 표시. 비어 있으면 "이날은 일정이 없어요."
- 오른쪽 위 "+"(더보기 아이콘 왼쪽): 추가 시트. 칸: 제목, 날짜, 하루 종일 스위치, 시각, 반복(없음/매일/매주/매달; 매주면 요일 7개 토글), 알림(정시/10분 전/30분 전/1시간 전/하루 전/없음, 기본 10분 전), 영역(선택), 메모.
- 줄을 누르면 상세 시트: 고치기, 반복 일정이면 "이번만 건너뛰기", "이후 반복 끝내기", "모두 지우기", 한 번짜리면 "지우기". 지우기류는 확인 시트를 거친다. 사용자가 한 일이라 적용 뒤 토스트에 되돌리기.
- 줄을 왼쪽으로 밀면 "건너뛰기"(반복) 또는 "지우기"(한 번짜리). 기존 `SwipeRow`.

### 9.3 오늘 화면

- 컨디션 블록 다음에 **오늘 일정** 블록: 오늘 일정(최대 5줄, 넘으면 "스케줄에서 {n}개 더 보기"). 일정이 없으면 블록을 숨긴다.
- 놓친 알림이 있으면 오늘 일정 블록 위에 한 줄씩: "놓친 알림 · 14:00 치과", 오른쪽 닫기(×) → `dismiss_missed_reminder`. 다음 날(논리적 날짜)에는 보이지 않는다.

### 9.4 메모 탭 (`/memos/`)

- 큰 제목 "메모", 오른쪽 위 "+"와 더보기. 그 아래 검색창(입력 300ms 뒤 `GET /memos?q=`).
- 목록: 고정 묶음("고정됨")이 먼저, 그다음 "메모". 줄 = 제목(굵게), 둘째 줄에 고친 날("오늘 14:02", "어제", "10월 21일")과 미리보기, 영역 점. 비서가 만든 메모는 "비서" 표시.
- 줄을 왼쪽으로 밀면 "고정"/"고정 풀기", "지우기"(되돌리기 토스트).
- 보기·쓰기 화면(`/memos/view/?id=`, 새 메모는 `?new=1`): 처음엔 바로 쓰기 상태(키보드 올라옴). 입력은 글 상자 하나, 키보드 위 작은 도구 줄(목록, 체크박스, 굵게, 영역, 완료). "완료"나 화면을 떠나면 저장한다(입력이 멈추고 1초 뒤에도 저장). 저장한 메모를 다시 열면 읽기 상태로 렌더링하고, 본문을 누르면 쓰기 상태가 된다. 읽기 상태에서 체크박스를 누르면 그 줄만 바뀐다.
- 오프라인이면 읽기만(SP5 원칙). 쓰던 글은 `localStorage`에 초안으로 둔다(그 기기의 편의, try/catch).

### 9.5 채팅 시트

- **대화 목록**: 시트 머리 왼쪽에 목록 버튼. 누르면 시트 안에서 목록 화면으로 넘어간다: 검색창, 날짜 묶음("오늘", "어제", "이번 주", "10월"), 줄 = 제목 + 요약 앞 한 줄 + 시각. 체크인 대화는 제목 앞에 "체크인". 맨 위 "새 대화" 버튼. 줄을 밀면 "지우기"(확인 시트). 줄을 누르면 그 대화를 읽기로 연다(`/conversations/{id}/messages`). 그 상태에서 보내면 `conversation_id`를 실어 잇는다(7.3).
- **새 대화**: 시트 머리 오른쪽(닫기 왼쪽)에 "새 대화" 아이콘도 둔다. 누르면 `POST /conversations/new` 뒤 빈 채팅.
- **퀵 칩 줄**(입력창 바로 위, 가로로 밀기, 칩 = 작은 아이콘 + 라벨, 높이 32px):
  - 고정 4개와 보내는 문장: `할 일 추가` → "할 일 추가할래요", `일정 추가` → "일정 하나 추가할래요", `메모하기` → "메모 하나 남길래요", `오늘 정리해줘` → "오늘 정리해줘".
  - 맨 앞 1개(위에서 처음 맞는 것): (1) 답하지 않은 체크인 회차가 답장 창 안 → `체크인 하기` → "체크인 할게요"(그 회차 대화로 간다). (2) 일요일이고 이번 주 회고가 열려 있음 → `이번 주 돌아보기` → "이번 주 돌아볼래요". (3) 3시간 안에 시작하는 일정 → `다음 일정 보기` → "다음 일정 알려줘". 없으면 고정 4개만.
  - 판단 재료는 `GET /today`(체크인·회고 상태, 오늘 일정)로 앱이 정한다. BE에 새 경로가 없다.
  - 읽기 전용(오프라인, 답 오는 중)이면 칩을 흐리게 하고 누를 수 없다.
  - 빈 채팅 화면은 따로 만들지 않는다(앱 스레드의 "추천 질문 줄" 계획을 이것으로 대신한다. 합의).
  - 참고: Dahun 회사 프로젝트의 입력창 위 퀵 칩(가로 슬라이드, 아이콘 + 라벨, 누르면 정해진 문장 전송)을 동작 참고로만 삼았다. 코드·자산은 가져오지 않는다.

### 9.6 되돌리기 숨기기

- 채팅의 활동 상자(`MessageView`의 `ActivityBox`)를 한 줄로 바꾼다: "✓ {confirmation}"(보조 글자색, 버튼 없음). 확인 전(R4b 이전) 상태 표시는 그대로 한 줄 문구로.
- 같은 때 토스트에 그 활동의 "되돌리기"를 **6초** 보인다(지금 토스트 그대로, 시간만 맞춘다). 한 답에 활동이 여럿이면 마지막 것 하나만 토스트로, 문구는 "✓ {n}개를 바꿨어요".
- 더보기 → 기록 화면의 줄별 되돌리기는 그대로다.
- `chat/hideCoveredActivity.ts`와 테스트, SP6 스펙 5.5.5/F6 활동 줄 규칙을 이 규칙으로 고친다(앱 스레드와 합의).
- 생성형 카드(`ui_result`, `ui_period_list`) 안의 되돌리기 버튼도 뺀다. 카드는 결과만 보인다.

### 9.7 설정 (더보기 → 설정)

- **체크인 시간** 묶음: 평일 아침, 평일 저녁, 주말 아침, 주말 저녁 네 줄. 누르면 iOS 시간 선택기(10분 단위). 줄 아래 작은 글씨 "주말 저녁은 일요일 주간 회고 시각이기도 해요." 바꾸면 "내일부터 적용돼요" 또는 "오늘부터 적용돼요" 토스트.
- **아이폰 캘린더에 구독** 묶음: "구독 주소 만들기" → 주소 보이기와 "복사", "주소 다시 만들기"(확인 시트 "이전 주소는 더 이상 갱신되지 않아요."). 안내 한 줄: "아이폰 설정 → 캘린더 → 계정 → 계정 추가 → 기타 → 구독 캘린더 추가에 붙여 넣어요. 폰에서 Tailscale이 켜져 있을 때 갱신돼요."

### 9.8 생성형 UI

- 새 완성 카드 `ui_events`: 그날 일정 1~10개 목록(시각, 제목, 영역 점, 반복 표시). 두뇌가 일정 목록을 보여 줄 때 쓴다. 누르면 스케줄 탭 그날로.
- 일정 확인(`update_event`, `delete_event`, `set_checkin_time`)은 기존 `needs_confirm` 확인 카드를 그대로 쓴다.
- 카탈로그 버전: SP8·다른 BE PR과 겹치면 먼저 머지되는 쪽이 다음 번호를 가진다(SP7 때와 같은 합의).

## 12. 테스트

**스파이크 (첫 티켓)**

- S1: 마이그레이션 번호 빈칸(013~015 없이 016) 처리 확인. `pytest tests/store/test_migrations.py -k gap` → 통과 또는 순서 규칙 문서화.
- S2: 노트북 SQLite가 FTS5 `trigram`을 지원하는지. `python -c "import sqlite3; c=sqlite3.connect(':memory:'); c.execute(\"create virtual table t using fts5(x, tokenize='trigram')\"); print(sqlite3.sqlite_version)"` → 3.34 이상, 오류 없음. 안 되면 `LIKE` 검색으로 바꾼다.
- S3: Agent SDK 세션 파일 위치와 지우기(7.7), 아이폰 캘린더가 테일넷 HTTPS 주소의 `.ics`를 구독하는지(Dahun 폰으로 한 번).

**BE (`pytest`)**

- `expand()` 표 테스트: 매일, 매주(월·수·금), 매달 31일(2027-02-28로 옮김), `repeat_until`, 건너뛰기, 하루 종일. 기간 62일 초과는 422.
- 알림 tick: R1~R4 각각, 공백 25분(늦게 보냄 "15분 남았어요"), 공백 50분(missed), 늦은 알림 4개 중 3개만 보냄, 시각 바꾸면 앞으로의 행 지움, 지난 `remind_at`은 안 보냄, 하루 상한 30.
- 마이그레이션 016: 시각 있는 열린 할 일 2개 → 일정 2개 + 할 일 `deleted_at`, 끝낸 할 일은 그대로. `create_task(scheduled_at=…)` → 안내 문구.
- 메모: 만들기·고치기(409 충돌)·고정 상한 10·지우기·30일 뒤 완전 삭제, `trigram` 검색 "사피", 2글자 검색 LIKE, 제목 추출, 도구 결과에 `redact()`.
- 대화: 닫힘 → 요약 큐 → 제목·요약 저장(가짜 두뇌), 상한·오류 시 대체 제목, 짧은 대화는 두뇌 안 부름, `conversation_id`로 잇기(resume 성공/실패 경로), 새 대화, 지우기(원문 기록 줄 바뀜, 목록에서 빠짐), 말아 넣기(31번째 메시지에서 새 세션, 입력에 요약 + 6줄).
- **새 세션 입력에 다른 대화 원문이 없다**: 대화 A에 고유 문자열을 남기고 닫은 뒤 새 대화 B의 첫 두뇌 입력에 그 문자열이 없음을 확인(완료 조건 9).
- 체크인 시간: 범위 밖 422, 적용 시점 표(오늘 회차 있음/없음 × 새 시각 지금 앞/뒤), 주간 회고가 주말 저녁을 따라감, 재시작 없이 `due_between`이 새 값.

## 14. 마이그레이션과 되돌림

- 016~018은 추가만 한다(새 표, 새 칸). 016의 할 일 옮기기만 기존 행을 바꾼다. 되돌릴 때는 DB 백업으로(SP6 updater가 배포 전 백업, 스키마가 바뀌면 복원).
- 앱은 BE보다 먼저 배포돼도 깨지지 않게 새 필드·경로가 없으면 그 블록을 숨긴다(SP5 관대한 읽기).

## 15. 미결 사항 (Dahun 확인)

Dahun이 고르지 않은 아래 선택은 비서의 추천이다. 바꾸고 싶은 것만 알려 주면 된다.

1. 하루 종일 일정의 알림 기준 09:00(5.1).
2. 늦게 보내는 알림 최대 3개, 하루 알림 상한 30(5.3).
3. 알림 칸에 "알림 없음"을 더함(Q2 보기에는 없었다).
4. 메모 검색어 2글자 이하는 LIKE(6.1), 지운 메모 30일 보관(6.1).
5. 요약 하루 15개, 말아 넣기 기준 사용자 메시지 30개, 최근 6줄(7.2, 7.4).
6. 대화 지우기는 원문 기록에서도 지우고 되돌릴 수 없음(7.7).
7. 체크인 시간 허용 범위 아침 05:00~11:30, 저녁 15:00~23:30, 10분 단위, 주간 회고가 주말 저녁을 따라감(8).
8. 퀵 칩 문장(9.5)과 앞 칩의 "3시간 안" 기준.
9. 토스트 되돌리기 6초(9.6).

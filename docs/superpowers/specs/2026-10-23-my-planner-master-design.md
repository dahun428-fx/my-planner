# my-planner 마스터 설계

- 상태: 초안 v2 (리뷰 1회 반영), Dahun 검토 대기
- 작성일: 2026-10-23
- 용어: [`GLOSSARY.md`](../../../GLOSSARY.md)의 뜻으로만 쓴다. 되돌리기 어려운 결정은 [`docs/adr/`](../../adr/)에 기록한다.
- 범위: 전체 비전, 하위 프로젝트 4개의 경계, 모두가 공유하는 인터페이스. 각 하위 프로젝트의 상세 설계는 별도 스펙에서 다룬다.

## 1. 목적

사용자가 인생 곡선을 점검하고, 일·주·월·분기·년 주기의 할 일과 회고를 이어 갈 수 있게 돕는 **개인 AI 비서**를 만든다. 비서는 텔레그램으로 먼저 말을 걸고, 정리와 초안을 대신 하며, 결정은 사용자가 한다.

이 프로젝트에서 사용자가 직접 만드는 것은 **하네스와 루프**다. 판단과 대화는 두뇌(Claude Agent SDK)가 맡는다.

### 1.1 성공 기준

1. 6개월 뒤에도 사용자가 비서를 계속 쓰고 있다.
2. 비서를 쓰고 나서 사용자가 덜 불안하다고 느낀다.
3. 처리한 할 일의 개수는 성공 기준이 아니다.

### 1.2 설계 원칙

| # | 원칙 | 설계에 주는 영향 |
|---|---|---|
| P1 | 피로를 늘리지 않는다 | 우선순위는 주기당 최대 3개, 첫 걸음은 15~30분. 하루 연락은 아침 브리핑과 저녁 체크인 두 번이 기본. |
| P2 | 목표는 마감일이 아니다 | 나이나 시점으로 압박하는 문구, 지연 경고를 만들지 않는다. |
| P3 | 휴식도 정당한 목표다 | 휴식도 경험치를 준다. 휴식은 "삶의 질" 영역의 정상적인 할 일이다. |
| P4 | 벌 대신 신호 | 체력 피해, 연속 기록, 기간 한정 보상을 쓰지 않는다. 내려간 스탯은 디버프와 회복 퀘스트로만 알린다. |
| P5 | 데이터는 사용자 PC에 | 원본 데이터는 노트북에만 둔다. GitHub 저장소에는 코드와 문서만 올리고, 데이터 폴더는 `.gitignore`로 제외한다. 예외: 자동 복구의 장애 이슈에는 가린 진단 정보(SP6 7장 허용 목록)만 올린다. |
| P6 | 원본 하나, 색인은 다시 만들 수 있게 | 각 데이터는 원본이 하나다. 검색 색인과 집계는 원본에서 언제든 다시 만들 수 있어야 한다. |
| P7 | 저장소는 도구 뒤에 | 두뇌는 파일이나 DB를 직접 만지지 않고 하네스 도구로만 접근한다. 내부 구현을 바꿔도 프롬프트와 다른 모듈은 바뀌지 않는다. |

### 1.3 하지 않는 것

- 다른 사람에게 비서를 제공하는 것 (단일 사용자 전용)
- 클라우드 서버 운영 (실행 환경은 사용자 노트북뿐)
- 그래프 DB
- 클라우드 임베딩 API
- 모바일 앱 (텔레그램이 모바일 화면 역할)

```

                 │            │   ▲                │                     │
                 │            ▼   │                ▼ 도구 호출            │
                 │          loop (스케줄러, 회차 기록, 따라잡기)          │
                 │            │                                         │
                 │            ▼                                         │
                 │   tools: tasks · memory · curve · status             │
                 │            │                                         │
                 │            ▼                                         │
                 │   data/ (md 원본) + state/planner.db (SQLite)         │
                 │                                                      │
                 │   dashboard (로컬 웹, 읽기 전용) ──▶ 같은 도구 계층     │

### 3.1 구성 요소

| 구성 요소 | 하는 일 | 의존 |
|---|---|---|
| `bot` | 텔레그램 수신과 발신. 사용자 계정 외 메시지는 버린다. 판단하지 않는다. | 텔레그램 Bot API |
| `harness core` | 메시지와 회차를 받아 두뇌 세션을 열고, 시스템 프롬프트와 허용 도구를 정해 실행하고, 답을 봇으로 돌려준다. | bot, brain, tools |
| `brain` | Claude Agent SDK 세션. | Claude Code CLI(설치됨), 구독 로그인 |
| `loop` | 주기별 회차를 예정하고 실행 기록을 남긴다. 깨어나면 놓친 회차를 따라잡는다. | SQLite `runs` 테이블 |
| `tools` | 두뇌에 노출되는 하네스 기능. 영역별 모듈로 나눈다. | data, state |
| `dashboard` | 상태창과 인생 곡선을 보여 주는 로컬 웹 화면. 쓰기 기능은 없다. | tools(읽기 전용) |

## 4. 하위 프로젝트

각 하위 프로젝트는 별도의 스펙 → 구현 계획 → 구현 주기를 가진다. 앞 단계가 끝나야 다음 단계 스펙을 확정한다.

| # | 이름 | 범위 | 완료 조건 | 의존 |
|---|---|---|---|---|
| SP1 | 비서 코어 | 봇(본인 잠금), harness core, 두뇌 세션, loop(아침 브리핑, 저녁 체크인, 주간 회고, 따라잡기), 할 일과 컨디션 도구와 SQLite, 원문 기록 저장, 시스템 로그, 작업 스케줄러 등록 | 7일간 `runs` 테이블의 예정 회차가 모두 `done` 또는 따라잡기 규칙에 맞는 `skipped`이고, 텔레그램으로 할 일을 추가·완료·이동할 수 있다 | 없음 |
| SP2 | 기억 계층 | 정리 루프, 기억 카드 생성·갱신·감쇠, 로컬 임베딩 + sqlite-vec + FTS5, `search_memory`, `/memory` | 2주 사용 후 "예전에 ~했을 때"류 질문에 근거 카드와 함께 답한다 | SP1 |
| SP3 | 인생 곡선 + 상태창 | 과거 그래프 인터뷰, 월·분기·연 회고 루프, 사다리 점수와 영역 점수 초안, 사건과 챕터, 레벨·경험치·스탯·디버프·퀘스트, `/status`, 차트 이미지 | 첫 월간 회고에서 점수 초안과 레이더 차트를, 첫 분기 회고에서 곡선 그래프를 받는다 | SP1, SP2 |
| SP4 | 웹 대시보드 | 로컬 웹 화면: 상태창, 인생 곡선, 퀘스트, 기억 카드 열람 | 브라우저에서 `/status`와 같은 데이터를 보고, 곡선을 기간별로 확대·축소할 수 있다 | SP3 |
| SP6 | 자동 복구 | 노트북 감시자·업데이터(medic), GitHub Actions 수리(Claude Code 액션)·CI·하트비트, 배포 롤백, 브라우저 에러 보고 ([SP6 스펙](2026-10-24-sp6-auto-recovery-design.md)) | 주입한 결함이 사람 손 없이 이슈 → 수리 PR → 머지 → 노트북 배포까지 가고, 확인 실패 시 이전 커밋으로 돌아간다 | SP1, SP3-4 API |

## 5. 공유 인터페이스

모든 하위 프로젝트가 따르는 계약이다. 바꾸려면 이 문서를 먼저 고친다.

### 5.1 저장소 폴더 구조

```
my-planner/

├── docs/                       # 스펙, 계획, ADR (Git 관리)
├── src/my_planner/
│   ├── bot/                    # 텔레그램 입출력
│   ├── harness/                # 세션 실행, 프롬프트, 권한, 훅
│   ├── loop/                   # 스케줄러, 회차 기록, 따라잡기
│   ├── tools/                  # 두뇌에 노출되는 도구 (tasks, memory, curve, status)

│   ├── reviews/<cadence>/<period>.md     # 예: week/2026-W43.md, month/2026-10.md
│   ├── curve/                  # SQLite에서 생성한 곡선 내보내기 (사람용)
│   └── exports/tasks.md        # SQLite에서 생성한 사람용 보기
├── state/                      # (.gitignore)
│   ├── planner.db              # SQLite 원본: 할 일, 회차, 컨디션, 점수, 사건, 상태창 원장
│   ├── index.db                # SQLite 색인: FTS5, sqlite-vec (다시 만들 수 있음, 백업 안 함)
│   ├── logs/
│   ├── backups/                # planner-YYYY-MM-DD.db 14개, pre-deploy-<sha>.db 5개, failed-<sha>/ 3개 (SP6)
│   ├── medic.db                # SP6 감시자 상태: 장애, 로그 읽은 위치, 배포 기록

│   └── my-planner.lock         # 단일 실행 잠금
├── .github/                    # SP6 워크플로(ci, repair, repair-sweep, heartbeat, vercel-failure), 수리 프롬프트

### 5.2 원본과 색인

| 데이터 | 원본 | 색인·파생 (다시 만들 수 있음) |
|---|---|---|
| 할 일, 우선순위, 첫 걸음 | SQLite `tasks`, `task_areas`(다대다), `priorities`, `task_events`(상태 변경 이력) | `data/exports/tasks.md` |
| 회차 기록 | SQLite `runs` | 없음 |
| 컨디션 | SQLite `conditions` (날짜, 1~5, 한 줄) | 없음 |
| 원문 기록 | `data/transcripts/` md | 없음 (색인하지 않음) |
| 기억 카드 | `data/memory/cards/` md | `index.db`의 FTS5 + sqlite-vec 색인 |
| 회고 (서술) | `data/reviews/` md (점수는 복사하지 않고 기간만 참조) | 없음 |
| 사다리 점수, 영역 점수, 사건, 챕터, 과거 그래프 | SQLite `curve_*` | 차트 이미지, `data/curve/*.md` 내보내기 |
| 레벨, 경험치, 스탯, 디버프 | SQLite `status_*` (원장 방식: 경험치 획득 기록을 쌓고 합계를 계산) | `/status` 카드 |

SQLite가 원본인 데이터는 백업 대상이다. 백업 방식은 SP1 스펙에서 정한다.

### 5.3 도구 계약

두뇌는 아래 도구로만 데이터에 접근한다(P7). 이름은 고정하고, 인자와 반환 형식은 각 하위 프로젝트 스펙에서 정한다.

| 모듈 | 도구 | 도입 |
|---|---|---|
| tasks | `add_task`, `update_task`, `complete_task`, `propose_tasks`, `confirm_tasks`, `move_task`(날짜만 바꾼다), `reopen_task`, `drop_task`, `list_tasks`, `set_priorities` | SP1 |
| condition | `record_condition` | SP1 |
| transcript | `read_transcript` (쓰기는 하네스가 자동으로 하고 두뇌에게 열지 않는다) | SP1 |
| memory | `search_memory`, `get_memory_card`, `upsert_memory_card`, `forget_memory_card` | SP2 |
| curve | `record_ladder_score`, `record_area_scores`, `add_milestone`, `get_curve` | SP3 |
| status | `get_status`, `grant_xp` | SP3 |

**두뇌 실행 계약** (모든 하위 프로젝트 공통)

- Agent SDK 기본 도구(읽기 전용 포함)는 **전부 끈다.** 하네스의 in-process MCP 도구만 `allowed_tools`로 명시해 허용한다.
- 사용자와 프로젝트 설정(`~/.claude`의 MCP 서버, 스킬, 플러그인, CLAUDE.md)은 불러오지 않는다(`setting_sources` 비움). 작업 폴더는 빈 전용 폴더다.
- 도구는 순수 Python 함수로 만들고, MCP 어댑터는 따로 둔다. 같은 함수를 봇 명령과 대시보드가 직접 부를 수 있다.

### 5.4 저장소 접근 규칙

- `store`는 하네스 내부 모듈 누구나 쓸 수 있다(loop, bot, tools, dashboard). **두뇌만** 반드시 도구를 거친다.
- 대시보드는 `store`의 읽기 전용 함수만 쓴다.
- 원본 DB(`state/planner.db`)와 색인 DB(`state/index.db`: FTS5, sqlite-vec)를 분리한다. 백업은 원본 DB만 한다.
- 원문 기록은 하네스가 저장하며, 저장 직전에 인증·식별 정보 패턴(비밀번호 문맥, 계좌번호, 주민번호)을 가린다.
- 각 데이터는 원본이 하나다. 회고 md에는 점수를 복사하지 않고 해당 기간을 참조만 한다. 사건, 챕터, 과거 그래프의 원본은 SQLite이고, md는 사람이 읽는 내보내기다.

### 5.5 대화와 시간

- **대화(conversation)**: 사용자와 비서가 주고받는 한 묶음. 회차가 대화를 열 수 있고, 회차에 대한 사용자의 답은 그 대화에 붙는다. 대화의 만료와 세션 이어가기 규칙은 SP1이 정한다.
- 메시지와 회차는 사용자 한 명 기준으로 **직렬 처리**한다.
- 시간대는 `Asia/Seoul`, 저장은 UTC. 하루의 경계는 새벽 04:00(그 전의 체크인은 전날로 기록).
- 하루 연락 횟수 상한: 비서가 먼저 보내는 메시지는 하루 최대 3회. 따라잡기와 회고는 다음 정규 연락에 합쳐 보낸다. 자동 복구의 결과 알림(SP6 6장)은 시스템 알림이라 이 상한에 세지 않고, 따로 하루 5개로 묶는다. 따라잡기 문구에 "놓쳤어요", "밀렸어요" 같은 지연 표현을 쓰지 않는다(P2).
- 텔레그램 명령(`/today`, `/status`, `/memory` 등)은 두뇌를 거치지 않고 하네스가 도구 함수를 직접 불러 답한다. 자연어는 두뇌가 처리한다.

### 5.6 인증과 비밀값

- 두뇌는 노트북의 Claude Code에 로그인된 사용자 본인 구독으로 실행한다. 단일 사용자 개인용이므로 허용 범위로 판단했다(참고: Claude Code Legal and compliance 문서). 다만 근거가 명확하지 않은 영역이라, 아래 중 하나가 생기면 API 키 인증으로 바꾼다: 다른 사람이 쓰게 될 때, 구독 사용량이 사용자의 Claude Code 사용을 방해할 때, Anthropic 정책이 바뀔 때.
- 인증이 실패하면(토큰 만료 등) 조용히 실패하지 않고 텔레그램으로 하루 한 번 알리며, 그 사이 회차는 `skipped(auth)`로 기록하고 다시 보내지 않는다(다시 로그인한 뒤 다음 정규 연락부터 이어진다). 따라잡기도 하루 두뇌 호출 상한에 포함한다.
- 텔레그램 봇 토큰과 사용자 텔레그램 ID는 `.env`에 사용자가 직접 넣는다. 코드와 Git에는 들어가지 않는다.
- 봇은 `.env`의 사용자 ID와 다른 발신자의 메시지를 읽지 않고 버린다.

## 6. 운영 고려사항

| 위험 | 대응 | 담당 |

| 재부팅 후 로그인 전 | 로그인 전에는 동작하지 않는다(로그인 시 시작). 로그인 후 따라잡기로 처리 | SP1 |
| 텔레그램 메시지 유실·중복 | `getUpdates` 롱폴링. 처리한 `update_id`를 SQLite에 기록해 중복 실행을 막는다. 텔레그램은 받아 가지 않은 메시지를 최대 24시간만 보관하므로, 하루 넘게 꺼져 있던 동안 보낸 메시지는 사라질 수 있다 | SP1 |
| 네트워크 끊김 | 텔레그램 수신 재연결, 두뇌 호출 재시도와 상한 | SP1 |
| 구독 사용량 소진 | 회차당 두뇌 호출 횟수와 턴 수 상한, 사용량 로그 | SP1 |
| 두뇌의 잘못된 쓰기 | 도구 단위 권한, 삭제는 복구 가능하게(소프트 삭제) | SP1, SP2 |
| 잘못된 기억 | 출처·확신도·마지막 확인일, 충돌 시 이력 보존, `/memory`로 삭제 | SP2 |
| 데이터 유출 | 데이터는 로컬, Git 제외, 인증·식별 정보 미저장. 백업은 로컬 디스크나 외장 디스크만 허용(클라우드 백업 금지). 대시보드는 `127.0.0.1`에만 바인딩 | 전체 |

## 7. 미결 사항

각 하위 프로젝트 스펙에서 정한다.

1. 아침 브리핑과 저녁 체크인의 기본 시각과 사용자 변경 방법 (SP1)
2. 따라잡기 규칙: 몇 시간 지난 회차부터 묶어서 요약할지 (SP1)
3. SQLite 백업 방식과 주기 (SP1)
4. Python 배포판: Microsoft Store판에서 SQLite 확장(`enable_load_extension`)이 로드되는지 **SP1 스파이크에서** 확인한다. 안 되면 SP1부터 python.org 설치판 3.12로 venv를 만든다. `bge-m3` 용량과 GPU 사용은 SP2 착수 전에 검증
5. 경험치 규칙: 무엇에 얼마를 주는지 (SP3). SP1은 이를 위해 할 일 상태 변경 이벤트를 기록해 둔다
6. 웹 대시보드 UI 제작 수단: UI UX Pro Max 스킬 사용 예정. PC의 Claude Code에 설치되어 있는지 SP4 착수 전에 확인

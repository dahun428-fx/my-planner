## 1. 목표와 완료 조건

2026-11-01 Dahun은 자기 "사회적 능력치"를 객관적으로 점검하려고 인바디, 사진, 이력서, 자산 화면, 입력 시트를 줬고, 공식 통계와 비교한 9개 축 점수(리포트 v1·v2, 프로젝트 폴더 `social-level/`)를 받았다. 이 점검이 일회성으로 끝나지 않고 **상태창의 고도화판**이 되기를 원한다. 상태창이 지금까지 쌓인 기록과 새로 준 자료로 "나"의 전체 상황을 비추는지도 함께 점검한다(Dahun 2026-11-01).

**완료 조건 (수용 기준)**

1. 앱 상태창의 영역 줄마다 두 숫자가 나란히 보인다: "만족 7"(분기 회고 영역 점수, 지금 스탯)과 "위치 59"(같은 영역의 객관적 위치, 0~100). 위치가 없는 영역은 "위치 —"이고 누르면 무엇을 넣으면 생기는지 한 줄로 안내한다.
2. 상태창에 "타고난 스탯" 묶음이 있고 키, 학벌, 집안이 각각 점수와 함께 보인다. 이 셋에는 디버프, 회복 퀘스트, 변화 표시가 없다.
3. 채팅에 인바디 결과지 사진을 올리면 비서가 숫자를 읽고 확인 카드("체지방률 17.5%, 골격근량 36.8kg, 측정일 2026-09-11 · 저장할까요?")를 낸다. 카드에서 숫자를 고칠 수 있고, "저장"을 누르면 측정값이 저장되고 건강 영역 위치가 다시 계산된다. 원본 사진은 SP10처럼 노트북에만 남는다.
4. 위치가 바뀌면 영역 줄에 바뀐 양과 이유가 보인다: "▲3 내 변화" 또는 "▼4 세상 변화". 내 변화로 내려간 경우에만 디버프 표시와 회복 퀘스트가 붙는다(ADR 0006, Dahun Q7 C). 세상 변화(기준표 갱신, 나이 구간 이동)로 내려간 경우 회색 글씨이고 디버프가 없다.
5. 상태창의 "객관적 위치 자세히"를 누르면 상세 화면(`/status/standing/`)이 열린다: 9축 레이더(두 비교 집단), 축별 막대와 근거·신뢰도·오차 범위, 결혼·연애 시장과 이직·커리어 시장 점수.
6. 각 점수 옆에 신뢰도(높음/중/낮음)와 오차 범위가 보인다. 입력이 빠진 하위 항목은 "미입력"으로 보이고, 빠진 항목은 점수에 가정값으로 들어갔다는 것이 한 줄로 보인다.
7. 대시보드 토큰으로 `GET /standing`을 부르면 `403`이다. 대시보드 상태창은 지금처럼 만족 점수만 보인다.
8. 노트북에서 `my_planner standing import <json>` 한 번으로 2026-11-01 점검 자료(프로젝트 폴더의 `social-level/data/`를 옮긴 JSON)가 측정값으로 들어가고, 상태창에 리포트 v2와 같은 점수(±1)가 나온다.
9. 상태창 커버리지 표(11장)의 "이번에 고침" 항목이 모두 반영되어 있다.
10. 14장의 자동 테스트가 모두 통과한다.

## 4. 접근안과 선택

| 안 | 내용 | 판단 |
|---|---|---|
| A. 측정값은 DB, 기준표는 저장소 파일, 점수는 읽을 때 계산 (선택) | `standing_measures` 표에 숫자와 출처를 쌓고, `src/my_planner/standing/benchmarks/2026.toml`에 통계 기준표를 둔다. 점수는 상태창처럼 매번 계산하고(SP3-4 9장의 "저장하지 않고 계산"), 분기마다 스냅숏 한 줄만 남긴다 | **선택**. 계산 규칙을 테스트하기 쉽고, 기준표가 코드 리뷰를 거친다. 스냅숏이 있어야 하락 이유를 나눌 수 있다 |
| B. 점수를 두뇌가 매겨 저장 | 두뇌가 자료를 보고 9축 점수를 적는다 | 버림. 같은 입력에 다른 점수가 나오고, 하락 이유를 나눌 수 없고, 근거를 따라갈 수 없다 |
| C. 기준표도 DB | 기준표를 표로 두고 앱에서 고친다 | 버림. 통계는 해마다 한 번 바뀌고 출처 검토가 필요하다. 앱에서 고칠 일이 없다 |

### 5.1 9축 → 6영역

|---|---|---|---|---|

| `health` | 건강·체력 | `health` | 아니오 | |

| `family` | 집안 | — | 예 | 타고난 스탯 |

- **영역 위치**: 영역에 축이 하나면 그 점수, 둘이면(건강) 가중 평균 `health 0.6 + looks 0.4`. `quality_of_life`에는 축이 없다. "위치 —"로 두고 상세 화면에 "삶의 질은 객관적 기준표가 없어요. 만족 점수와 생활 지표(잠, 걸음, 쉬는 저녁)로 봐요."를 보인다(15장 D2).
- 고정 축은 다시 채점하지 않는다: 입력이 바뀌지 않는 한 점수가 바뀌지 않고, 기준표가 바뀌어도 변화 표시를 하지 않는다(심리 전문가 소견 "고정 축은 내려놓기").

### 5.2 비교 집단

- (a) `national`: 전국, 같은 나이 구간(만 나이 5세 단위), 같은 성별. 기본 표시.
- (b) `peer`: 사는 권역과 직군이 같은 30대(지금 기준표는 "수도권 30대 IT 개발자, AI/ML"). 직업·경제력만 (a)와 다르고, 나머지 축은 (a) 값을 그대로 쓴다.
- 나이·성별·권역·직군은 프로필 측정값(6.1의 `profile_*`)에서 읽는다. 없으면 (a)만 계산하고 (b)는 "—"이다.

## 6. 측정값

### 6.1 `022_standing.sql`

```sql
CREATE TABLE standing_measures (
  id            INTEGER PRIMARY KEY,
  metric        TEXT NOT NULL,            -- 6.2 목록. 코드가 목록 밖 값을 거절한다
  value_num     REAL,                     -- 숫자 값
  value_text    TEXT,                     -- 범주 값(예: education_tier = 'seoul_mid_low')
  measured_on   TEXT NOT NULL,            -- 'YYYY-MM-DD' 측정일(올린 날이 아니라)
  source_kind   TEXT NOT NULL CHECK (source_kind IN ('photo','pdf','manual','shortcut','import','derived')),
  source_ref    TEXT,                     -- 'photo:<id>', 'body_day:<date>' 등. 원본 파일 경로는 두지 않는다
  confidence    TEXT NOT NULL DEFAULT 'mid' CHECK (confidence IN ('high','mid','low')),
  created_at    TEXT NOT NULL,
  deleted_at    TEXT,                     -- 지우기는 표시만(되돌리기 24시간)
  CHECK (value_num IS NOT NULL OR value_text IS NOT NULL)
);
CREATE INDEX standing_measures_metric ON standing_measures(metric, measured_on) WHERE deleted_at IS NULL;

CREATE TABLE standing_snapshots (
  period        TEXT NOT NULL,            -- 'YYYY-Qn'
  axis          TEXT NOT NULL,
  cohort        TEXT NOT NULL CHECK (cohort IN ('national','peer')),
  score         INTEGER NOT NULL CHECK (score BETWEEN 0 AND 100),
  bench_version TEXT NOT NULL,            -- 기준표 파일의 version
  inputs_json   TEXT NOT NULL,            -- 계산에 쓴 측정값 id와 값(하락 이유 나누기용)
  taken_at      TEXT NOT NULL,
  PRIMARY KEY (period, axis, cohort)
);
```

- 같은 `metric`의 값이 여럿이면 `measured_on`이 가장 늦은 것(같으면 `id`가 큰 것)을 쓴다. 지난 값은 추이 그래프와 하락 이유 나누기에만 쓴다.
- 측정값은 경험치를 주지 않는다. 대신 분기마다 처음으로 객관적 위치가 생기거나 갱신될 때 X14(10장).

SP15가 생기면 사진·PDF 길의 상대가 비서에서 라이프 매니저로 옮겨 간다. 그때까지는 비서 대화에서 받는다.

### 6.4 얼굴·관리 점수

- `face_rating`은 두뇌가 정면 사진을 보고 매긴 참고값(0~100)이고 `confidence='low'`로만 저장한다. 외모 점수에서 얼굴·관리 묶음 30% 안의 절반(15%)만 차지한다. 나머지 절반은 `grooming_rating`.
- 카드 문구에 "얼굴 점수는 조명·각도·취향에 따라 ±10 흔들려요."가 늘 붙는다.
- 같은 조건 사진(같은 거울, 같은 조명)끼리의 변화만 해석한다는 규칙을 비서 지시문에 둔다.

### 6.5 확인 카드와 `/actions`

- `ui_block` 종류 `measure_confirm`: `{rows: [{metric, label, value, unit, measured_on, editable: true}], source_ref}`. 카드는 SP9c 퀵 칩 카드와 같은 모양을 쓴다.
- `/actions save_measures {rows, source_ref}`: `confirm` 등급. 응답 확인 문구 "✓ 측정값 {n}개 저장 · {영역} 위치 {이전}→{새}". 되돌리기 24시간(그 줄들에 `deleted_at`).
- `/actions delete_measure {id}`: 상세 화면에서 밀어서 지우기. 되돌리기 24시간.
- 감사 기록(`actions_log`)에는 지표 이름과 개수만 남기고 값은 남기지 않는다(로그에 연봉·자산이 남지 않게).

## 8. 점수 계산

### 8.1 자리

- `src/my_planner/standing/score.py`: 순수 함수. 입력은 `Measures`(지표 → 최신 값과 id), `Bench`, `cohort`, `today`. 출력은 축마다 `AxisScore{axis, score, low, high, confidence, inputs, missing, assumed}`.
- `src/my_planner/standing/markets.py`: 시장 점수 두 개(가중 평균, 결혼시장 문턱 규칙은 쓰지 않음. 15장 D3).
- `src/my_planner/standing/drift.py`: 하락 이유 나누기(9장).

### 8.2 축별 규칙

리포트 v2의 규칙을 그대로 코드로 옮긴다. 정본은 프로젝트 폴더 `social-level/scoring-guide.md`와 `benchmarks/` 세 문서의 "채점 기준표" 절이다. 여기서는 바뀌는 점과 빈칸 처리만 적는다.

| 축 | 규칙 요약 | 빈칸이면 |
|---|---|---|
| 키 | Φ((키 − 평균)/SD) × 100 | 점수 없음 |
| 외모 | 몸 70%(허리 30·체지방 25·FFMI 25·BMI 10·관리 10의 가중 평균) + 얼굴·관리 30%(얼굴 15·관리 15) | 빠진 하위 항목은 50으로 가정하고 `assumed`에 적는다. 몸 하위 항목이 하나도 없으면 점수 없음 |
| 건강 | 심폐 20·근력 15·근지구력 10·혈압 15·혈당 10·LDL 10·간 5·흡연 5·음주 5·운동 습관 5 | 검진 수치 없이 `checkup_flag='normal'`이면 혈압·혈당·LDL·간을 각 100으로, `confidence`를 한 단계 내린다. 체력 실측이 없으면 `run_6k_min`·1RM으로 등급을 추정(`estimate`) |
| 직업 | 0.6 × 루브릭 백분위 + 0.4 × 연봉 백분위. 루브릭 = 회사 + 직무 + 연차·레벨 + 외부활동 + 리크루터 + 오퍼 보너스 | 리크루터·오퍼·외부활동 빈칸은 0으로 두되 범위 상단을 "있다면" 값으로 넓힌다(리포트 v2의 27~36) |
| 경제력 | 0.40 × 연봉 백분위 + 0.45 × 순자산 백분위 + 0.15 × 저축률 점수 | 저축률 빈칸은 25로 가정(재무 전문가 소견) |
| 관계 | 지지망 기본점 + 교류 가점 + 연애 상태 가점 − 외로움 | 지지망·교류 빈칸이면 범위 35~55, 점수는 가운데(45), `confidence='low'` |
| 자격 | 가장 높은 자격 기본점 + 나머지마다 +4, 상한 100 | 자격이 없으면 50 |
| 학벌 | 구간표 + 복수전공 +3 | 점수 없음 |
| 집안 | 가구 순자산 구간(60대 보정 −4) + 부양 부담 보정 | 점수 없음 |

- **오차 범위**: 축마다 `low`/`high`. 기본 ±5, `estimate` 기준표를 쓰면 ±8, `assumed`가 있으면 그 하위 항목이 0~100일 때의 범위로 넓힌다.
- **신뢰도**: `high` = 빈칸 없고 기준표가 공식, `mid` = 빈칸 1개 이하 또는 추정 기준표, `low` = 빈칸 2개 이상 또는 `face_rating`만으로 결정되는 항목이 있음.
- 계산 결과는 리포트 v2의 점수와 ±1 안이어야 한다(테스트 T3, 2026-11-01 가져오기 자료로).

### 8.3 시장 점수

- `시장 = Σ(축 점수 × 가중치) / 100`, 가중치는 기준표의 두 벌(결혼 20·18·13·10·10·9·7·7·6, 커리어 30·18·12·12·8·7·5·5·3).
- 점수 없는 축은 빼고 남은 가중치로 다시 나눈다. 빠진 축은 화면에 "빠짐"으로 적는다.
- 결혼시장 점수에는 늘 "나이·성격·가치관이 빠진 서류 스펙 점수"를 붙인다.

## 9. 하락 이유 나누기 (Q7 C)

### 9.1 스냅숏

- 분기마다 한 번, 분기 회고를 마칠 때(SP3-4 분기 회고 단계 끝) 그 시점의 축 점수를 `standing_snapshots`에 쓴다. 분기 회고가 없던 분기는 그 분기 마지막 날 하루 끝 작업이 쓴다(따라잡기, ADR 0004).
- 측정값을 처음 저장한 날 그 분기 스냅숏이 없으면 바로 하나 쓴다(첫 기준선).

### 9.2 계산

지난 스냅숏(입력 `I0`, 기준표 `B0`)과 지금(입력 `I1`, 기준표 `B1`, 나이 구간 포함)이 있을 때:

- 전체 변화 `Δ = S(I1, B1) − S(I0, B0)`
- 세상 변화 `Δw = S(I0, B1) − S(I0, B0)` (내 입력은 그대로 두고 기준표·나이 구간만 바꿨을 때)
- 내 변화 `Δm = Δ − Δw`

| 표시 | 조건 |
|---|---|
| "▲n 내 변화" | `Δm ≥ 2` |
| "▼n 내 변화" + 디버프 + 회복 퀘스트 | `Δm ≤ −3` (작은 흔들림은 무시. 심리 전문가 "±5 안은 해석하지 않음"에 맞춰 경계를 둔다. 15장 D4) |
| "▼n 세상 변화" (회색, 디버프 없음) | `Δw ≤ −2` |
| 아무 표시 없음 | 그 밖 |

- 둘 다 해당하면 두 줄로 보인다.
- 고정 축은 표시하지 않는다(5.1).
- 회복 퀘스트는 SP3-4 9.3과 같은 차례: SP15가 생기기 전에는 영역별 기본 문구, SP15 뒤에는 라이프 매니저의 제안 하나.

## 10. 상태창과 경험치

### 10.1 영역 줄

```
커리어      만족 7   위치 59 (IT 27)   ▼4 세상 변화
경제        만족 6   위치 60 (IT 50)
건강        만족 8   위치 82           ▲3 내 변화
관계        만족 5   위치 45 · 낮음
배움        만족 7   위치 95
삶의 질     만족 7   위치 —
```

- "위치"는 (a) 점수. (b)가 다르면 괄호에 "IT n". 신뢰도가 `low`면 "· 낮음".
- 디버프는 지금처럼 만족 점수 하락에도 붙는다(SP3-4 9.3). 위치의 "내 변화" 하락 디버프는 별도 표시(같은 모양, 다른 문구 "위치 하락")다.
- 금지어 검사(SP5 10장) 대상: "등수", "패배", "뒤처짐", "실패". 화면 문구는 "위치", "상위 n%" 대신 "위치 n"만 쓴다(15장 D5).

### 10.2 타고난 스탯

- 영역 목록 아래 한 묶음. "키 83 · 학벌 76 · 집안 66". 설명 한 줄: "바꿀 수 없는 출발점이에요. 다시 채점하지 않아요."

## 12. API

| 메서드·경로 | 누가 | 내용 |
|---|---|---|
| `GET /standing` | 앱 기기, API 토큰 | `{cohorts: {national, peer}, axes: [AxisScore…], areas: {career: {score, peer_score, drift}, …}, innate: […], markets: {marriage: {national, peer}, career: {…}}, bench: {version, effective_from}}` |

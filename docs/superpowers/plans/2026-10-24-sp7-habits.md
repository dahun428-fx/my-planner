# SP7 습관 체크 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan ticket-by-ticket. Steps use checkbox (`- [ ]`) syntax for tracking. 티켓 하나를 끝낼 때마다 `.claude/agents/code-reviewer.md`로 리뷰하고, 지적을 반영한 뒤 다음 티켓으로 간다.

**Goal:** 할 일과 나란히 매일·주 N회 습관을 두고, 앱 오늘 화면·습관 화면·저녁 체크인(텔레그램 버튼, 앱 카드)·대화에서 체크한다. 놓친 날은 저장도 계산도 하지 않는다.

**Architecture:**
- 새 표 `habits`, `habit_checks`(마이그레이션 012, 같은 파일에서 경험치 원장 CHECK 넓히기). 저장소 `store/repos/habits.py`.
- 쓰기는 SP3-4와 같은 두 갈래뿐이다: 두뇌 갈래(`Tools`의 습관 도구 6개)와 즉시 갈래(`apply_action`의 다섯 동작, 텔레그램 `hb:` 버튼). 활동·되돌리기·원장은 같은 트랜잭션.
- 읽기는 `store/views.py`의 `habit_dict`/`habits_view` 하나를 `/today.habits`, `GET /habits`, 두뇌 앞머리, `/habits` 명령, `ui_habit_check`의 `data.habits`가 함께 쓴다.
- 앱은 `ui_habit_check` 부품 하나(`HabitList`)를 오늘 블록, 체크인 카드, 대화에서 같이 쓰고, 탭 밖 화면 `/habits/`를 더한다.

**Tech Stack:** SP3-4·SP5와 같다(Python 3.12, aiohttp, python-telegram-bot, SQLite / Next.js 15 Pages Router 정적 내보내기, Vitest, Playwright). 새 의존성 없음.

**Spec:** [`docs/superpowers/specs/2026-10-24-sp7-habits-design.md`](../specs/2026-10-24-sp7-habits-design.md) (v2.1, main `15ec620`. 습관 ADR은 이 계획 PR에서 0011로 옮겼다: 자동 복구 ADR 0010이 먼저 머지됐다). 상위: [SP3-4 스펙](../specs/2026-10-24-sp3-4-life-curve-dashboard-design.md)(API 계약 정본), [SP5 스펙](../specs/2026-10-24-sp5-ops-app-design.md), [SP1 스펙](../specs/2026-10-23-sp1-secretary-core-design.md). 용어 [`GLOSSARY.md`](../../../GLOSSARY.md), 결정 [ADR 0006](../../adr/0006-no-punishing-game-mechanics.md), [ADR 0011](../../adr/0011-habits-are-not-recurring-tasks.md).
- 스펙과 이 계획이 다르면 스펙이 맞다. 티켓은 스펙을 다시 쓰지 않고 절을 가리킨다.

## Global Constraints

- (5.1) "안 한 날은 행이 없다. '놓친 날'을 저장하거나 계산하는 함수를 만들지 않는다."
- (5.1) "활성 습관 상한 10개(`active`만 센다)." (5.3) "오늘 포함 7일(오늘과 그 앞 6일)만 체크·취소할 수 있다."
- (5.6) X11 "습관 체크 | 3 | `habit_check` / `habit:<id>:<날짜>` | 습관·날짜마다". 주간 목표 보상은 두지 않는다(기간 한정 보상). "체크 취소, 쉬어 가기, 그만두기 모두 원장을 건드리지 않는다." "쉬는 날(X9)은 그대로다."
- (5.4 규칙 H6) "회차 차례에서 `check_habit`, `uncheck_habit`, `add_habit`은 거절한다". (규칙 H7) 회차 차례의 `set_habit_status(archived)`, `update_habit`은 `needs_confirm`, `paused`는 바로.
- (5.5) 체크 활동의 대상은 `habit:<id>:<날짜>` 하나. `WATCH_ONLY_TARGETS`는 쓰지 않는다.
- (7장) 금지어: SP5 목록("연속", "스트릭", "달성률", "밀렸다", "놓쳤다", "실패")에 "끊겼", "며칠째", "남음"을 더한다. 새 문구는 스펙 부록 A 그대로.
- (8장) 습관 제목은 활동 `summary`, 확인 문구에는 들어가고 로그에는 넣지 않는다(id와 결과만). 상태창 "최근 경험치"에 넣지 않는다.
- (9장) 새 화면·부품 CSS 모듈은 모두 `web/app/src/pages/_app.tsx`에서 불러온다. 색은 테마 토큰만. 카탈로그 판 번호는 BE PR 머지 순서로 다음 번호(지금 `2026-10-24.2`).
- SP3-4·SP1 Global Constraints(단일 작성자, `mode=ro` 읽기, 시각 UTC, 논리적 날짜 04:00, 영역 6개, 하루 3회 상한)는 그대로다.

## 작업 방식

- TDD 주기와 명령은 SP3-4 계획 "작업 방식" 그대로다: 슬라이스마다 테스트 → `python -m pytest <노드 id> -v` FAIL → 구현 → PASS.
- 티켓 끝 검증(BE): `python -m pytest -q` → `0 failed`, `ruff check src tests` → `All checks passed!`. 앱: `cd web/app && npm run typecheck && npm run lint:copy && npm test && npm run test:tz && npm run build && npm run check:csp` → 모두 통과(SP5 계획의 공통 앱 검증).
- 생성자 새 인자는 키워드 전용, 기본값 `None`(SP1·SP3-4 시험이 그대로 돈다): `Tools(habits=…)`, `TelegramSender(habits=…)`, `build_preamble(habits=…)`, `checkin_cards(habits=…)`.
- 티켓 이름은 `SP7-NN`이다. 스펙 5.4의 도구 규칙 H1~H8은 이 문서에서 "규칙 H6"처럼 쓴다.
- 금지어 검사는 사용자에게 보이는 문구(텔레그램·앱 문구, 확인 문구, 부록 A)와 프롬프트에만 한다. 코드 주석·독스트링은 범위 밖이다("끊겼"가 이미 있다).
- 시험 날짜: 2026-10-24(토) 저녁 체크인 18:00, 2026-10-26(월)~30(금) 17:30, 주간 회고 일요일 18:00. 주 경계는 `clock.period_of(Cadence.week, d)`.

## Review Focus

1. **새벽 00:00~03:59의 체크**: 10/25 01:30에 누른 습관은 10/24(논리적 날짜)에 기록되고, 10/26(월) 02:00의 체크는 전 주(`2026-W43`)에 센다. → SP7-02 `test_check_at_0130_counts_previous_logical_day`, SP7-01 `test_monday_0200_is_previous_iso_week`
2. **같은 습관을 두 통로에서 거의 동시에 누름**(텔레그램으로 먼저 답한 저녁 체크인에서, 앱으로 습관 체크 직후 텔레그램 버튼): 두 번째는 토글이라 취소가 된다. 텔레그램 쪽은 누르기 전 DB 상태로 판단하고, 다시 그린 버튼은 모든 습관을 DB 상태로 보여 준다. → SP7-04 `test_button_after_app_check_on_telegram_answered_run_unchecks_and_redraws_from_db`
3. **제목 공백·대소문자·이모지**: `" 운동 "`은 `"운동"`으로 저장되고 같은 제목 거절에 걸린다. 이모지가 든 40자 제목은 받고, 텔레그램 버튼 글자는 코드포인트 기준 10자로 자른다. → SP7-02 `test_title_strip_and_duplicate`, SP7-04 `test_button_label_truncates_by_codepoint`
4. **습관 상한에 닿은 뒤 되돌리기**: 활성 10개에서 쉬어 가기 하나 → 새 습관 추가(10개) → 쉬어 가기 되돌리기 → 11개, 이때 새 추가·다시 시작은 거절, 체크는 된다. → SP7-02 `test_undo_pause_can_exceed_cap_then_add_rejected`
5. **ISO 연도 경계**: 2027-01-01(금)의 `week`는 `2026-W53`, 2026-12-28~2027-01-03의 체크는 한 주로 센다. → SP7-01 `test_iso_week_53`

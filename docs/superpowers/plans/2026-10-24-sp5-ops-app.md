# SP5 운영 앱 "비서" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan ticket-by-ticket. Steps use checkbox (`- [ ]`) syntax for tracking. 티켓 하나를 끝낼 때마다 `.claude/agents/code-reviewer.md`로 리뷰하고, 지적을 반영한 뒤 다음 티켓으로 간다.

**Goal:** Dahun의 아이폰 홈 화면에서 비서를 운영하는 PWA "비서"를 `web/app/`에 만든다. 오늘 보기, 대화와 생성형 화면 조각, 체크인 답장, 할 일 고치기, 기록과 되돌리기, 알림 설정을 텔레그램과 같은 BE 상태 위에서 한다.

**Architecture:**
- Next.js 15 Pages Router 정적 내보내기(`out/`)를 Vercel에 올리고, 폰 브라우저가 Tailscale로 BE `/api/v1`을 직접 부른다(스펙 4.1~4.2, ADR 0009). 서버 코드는 없다.
- 데이터 흐름은 한 방향이다: 화면은 `GET`으로 읽고, 쓰기는 `POST /actions`·`/undo`·`/chat`으로 보낸 뒤 그 화면의 `GET`을 다시 부른다. 규칙(자율성, 확인, 상한)은 BE가 정하고 앱은 응답을 그대로 그린다(4.1).
- 계획은 **세로 티켓**이다. 순서: 뼈대와 토큰 → 연결 → 쓰기·알림 줄 → 오늘 → 화면 부품 → 대화 → 체크인 → 할 일 → 기록 → 설정·푸시·서비스 워커 → CSP 실행·눈 확인 → 배포 → 실기기 수용.
- BE가 아직 없어도 돈다: 모든 화면 시험은 MSW 고정 자료로 돌고, 고정 자료는 BE `GET /schema`로 검증한다(A00). 대화 계약 시험만 BE 티켓 06의 기준 SSE를 기다린다(A05).

**Tech Stack:** Node 20+, Next.js 15 Pages Router(`output: "export"`), React(Next 15가 받는 판), `ai` 5.x + `@ai-sdk/react` 5.x, `@cfworker/json-schema`, `idb-keyval`, CSS Modules, Vitest + Testing Library + MSW + jsdom, Playwright(Chromium, 390×844), `json-schema-to-typescript`. 판은 A00의 `web/app/package-lock.json`에 고정한다. 대시보드(`web/dashboard/package-lock.json`)가 먼저 있으면 같은 판을 쓴다.
- 화면 제작: taste 스킬(github `Leonxlnx/taste-skill`, 앱 스타일 `achromatic-ledger`, seed `1081995691`)의 `lint.mjs --app`과 UI UX Pro Max 스킬의 점검 항목. 디자인 결정은 이미 스펙 5장과 시안에 있다. 다시 정하지 않는다.

**Spec:** [`docs/superpowers/specs/2026-10-24-sp5-ops-app-design.md`](../specs/2026-10-24-sp5-ops-app-design.md) (확정 v3, main `32158cc`). API 계약 정본: [SP3-4 스펙](../specs/2026-10-24-sp3-4-life-curve-dashboard-design.md) 6장·7장·14장. BE 구현 순서: [SP3-4 계획](2026-10-24-sp3-4-life-curve-dashboard.md). 시안: https://claude.ai/artifact/76cZTQhG8ix1MVuvxQ6XAp. 결정: [ADR 0009](../../adr/0009-ops-app-static-pwa-keeps-read-snapshot.md).
- 스펙과 이 계획이 다르면 스펙이 맞다. 이 계획이 스펙의 빈 곳을 정한 자리는 끝의 "스펙 빈 곳과 이 계획의 결정"에 모았고, 티켓 A13이 스펙에 옮긴다.

## Global Constraints

스펙의 문장을 그대로 옮긴다(절 번호). 모든 티켓의 요구 사항에 들어간다.

**비밀과 기기 저장**
- (4.7) "토큰은 빌드, Vercel 환경 변수, 저장소, 로그, 오류 보고 어디에도 넣지 않는다(SP3-4 14장). 화면에도 보이지 않는다(입력 칸은 `type="password"`)."
- (4.7 표) 기기에 두는 것은 `mp.beUrl`, `mp.token`, `mp.lastHealthOk`, `mp.pushId`, `mp.theme`(빈 곳 9)와 IndexedDB `snap:*`, `parts:*`(200개), `catalog`뿐이다. "7일이 지나거나 '이 기기 연결 해제'를 하면 지운다."
- `console.*`에 토큰, 메시지 본문, 할 일 제목, 푸시 `endpoint`를 쓰지 않는다. 테스트 고정 자료는 꾸며 낸 내용만.

**CSP와 스타일**
- (4.7) CSP 문자열은 정확히 `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self' ${NEXT_PUBLIC_CONNECT_SRC}; base-uri 'none'; form-action 'none'; worker-src 'self'; manifest-src 'self'`이고 `_document`의 **첫** `<meta>`다. `frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, 최소 `Permissions-Policy`는 `vercel.json` 헤더다.
- (4.3) "컴포넌트에 `style={{…}}`를 쓰지 않는다. 줄 밀기·시트 끌기처럼 움직이는 값은 `ref`로 CSSOM(`el.style.transform = …`)에 직접 쓴다." CSS Modules + `src/styles/tokens.css`만.
- (4.3) 조각 검사는 `@cfworker/json-schema`. `ajv`, `eval`, `new Function`은 쓰지 않는다.
- (4.2) 서버 함수, API 라우트, `getServerSideProps`, 외부 글꼴·스크립트, Vercel 분석은 넣지 않는다.

**디자인 (5.1~5.3)**
- 색은 5.2 토큰만. "**파란색 하나(`--hue`)는 '비서가 한 일'에만 쓴다.**" 그리고 링크.
- 버린 것: 그라데이션, 보라·라벤더, 반짝이·AI 아이콘, 이모지, 쉬는 요소의 그림자("비서에게 말하기" 버튼 하나만 그림자), 유리 효과, 작은 대문자 라벨, 순번(01, 02).
- 글자 크기는 30 / 16 / 15 / 13 / 11, 굵기 400 / 600 / 700(제목만). 숫자는 `tabular-nums`, 시각은 `HH:MM` 24시간.
- 움직임은 `transform`과 `opacity`만(시트 280ms, 줄 밀기 200ms, 알림 줄 180ms). `prefers-reduced-motion`이면 움직이지 않는다. 화면 들어올 때 연출 없음.
- (9장) 터치 영역 44px 이상, 버튼은 `<button>`, 이동은 `<a>`, 아이콘만 있는 버튼은 `aria-label`, 색만으로 뜻을 전하지 않는다, 크기는 `rem`.

**문구 (10장)**
- 존댓말 "-요", 압박·평가·재촉 없음. 마감 시각, 남은 시간, 완료 개수와 비율은 보이지 않는다(P2, P4).
- 금지어: `src/my_planner/harness/prompts/system.md`의 `banned-words` 블록("밀렸다", "놓쳤다", "실패", "놓쳤어요", "밀렸어요", "늦었지만") + "연속", "스트릭", "달성률". 지나간 회차는 "지나감", 보내지 못한 것은 "안 갔어요".
- 화면의 한국어 문장은 모두 `src/lib/copy.ts`에 둔다. 영역 이름은 커리어, 경제, 건강, 관계, 배움, 삶의 질. 회차 이름은 SP3-4 부록 A 그대로(아침 브리핑, 저녁 체크인, 주간 회고, 다시 이어서).

**API 쓰기 (4.6, SP3-4 6.1)**
- `client_msg_id`(UUID v4)는 `/actions`, `/undo`, `/chat`에만 넣는다. 동작마다 새 값, 네트워크 오류로 같은 동작을 다시 보낼 때만 같은 값. 확인 시트의 "바꾸기"는 **새** 값(F6).
- 낙관적 반영은 할 일 체크 하나만. 오프라인에서는 쓰기를 모아 두지 않고 버튼을 끈다.
- 시각은 모두 `Asia/Seoul`로 보인다. 날짜 계산의 기준은 BE가 준 논리적 날짜(`/today.date`)다(빈 곳 3).

## 작업 방식

- 모든 명령은 `cd web/app` 뒤에 돈다. 슬라이스마다 시험 하나 → `npx vitest run <파일> -t "<이름>"`으로 FAIL(새 이름은 import 오류, 새 동작은 assertion) → 구현 → 같은 명령으로 PASS.
- 티켓 끝 검증(공통): `npm test` → `0 failed`, `npm run test:tz`(`TZ=America/Los_Angeles vitest run src/lib/time.test.ts`) → `0 failed`, `npm run typecheck` → 코드 0, `npm run lint:copy` → 코드 0. A00 뒤 모든 티켓은 `npm run build && npm run check:csp` → `CSP OK: 0 inline scripts, 0 inline styles, meta first`도 본다. 그다음 `code-reviewer` 리뷰, 커밋.
- 화면 시험의 고정 자료는 `src/test/fixtures/*.json`이고 `fixtures.test.ts`가 `schema.json`의 모델로 검증한다(A00). 새 고정 자료를 더하는 티켓은 그 표에 줄을 더한다.
- 시험 날짜: 2026-10-24(토)를 "오늘"로 둔다(`/today.date = "2026-10-24"`). 체크인 시각은 주말 일정(10:00, 18:00).
- BE 티켓이 머지되기 전에는 고정 자료로 만든다. 스키마가 바뀌면 `npm run gen:types`로 `schema.json`과 `types.gen.ts`를 다시 만들고 `fixtures.test.ts`가 깨지는 고정 자료를 고친다.

## Review Focus

스펙이 암시하지만 13장 시험 표가 다루지 않고, 쓰다가 먼저 부딪힐 다섯 가지. 시험은 맡은 티켓에 있다.

1. **자정과 04:00 사이의 "내일로"**: 01:30에 "내일로"를 누르면 논리적 날짜(`/today.date`)의 다음 날이어야 한다(기기 달력의 다음 날이 아니다). 기기 시간대가 한국이 아니어도 시각은 KST로 보인다. → A01 `time.test.ts`, A03 `Today.test.tsx`
2. **두 번 누르기**: 체크, "확정", "추가", "바꾸기"를 빠르게 두 번 누르면 요청은 하나만 간다(두 번째 누름은 응답이 올 때까지 무시). 다른 `client_msg_id`로 두 번 가면 할 일이 둘 생긴다. → A02 `actions.test.ts`
3. **다른 BE로 다시 연결한 뒤의 스냅샷**: 주소를 바꾸거나 연결을 해제한 뒤 오프라인이 되면 옛 BE의 할 일이 보이면 안 된다. 받은 지 7일이 지난 스냅샷도 보이지 않는다. → A03 `snapshot.test.ts`
4. **붙여 넣은 주소와 열쇠**: 앞뒤 공백·줄바꿈, 끝 `/`, 끝 `/api/v1`, 대문자 호스트는 정리하고, `http://`·범위 밖 주소는 이유와 함께 거절한다. 열쇠의 앞뒤 공백도 지운다. → A01 `connection.test.ts`
5. **푸시를 못 받는 기기**: Safari 탭(홈 화면 앱 아님), `PushManager` 없음, 권한 `denied`, 아이폰이 구독을 지운 경우에 앱이 멈추지 않고 5.5.7·F7 문구를 보인다. → A09 `push.test.ts`

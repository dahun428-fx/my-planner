# SP15 스파이크 S1: SDK 서브에이전트

2026-11-01, 클라우드 컨테이너(Linux, Python 3.12, claude-agent-sdk 0.2.173, 번들 CLI, 모델 claude-opus-5-5)에서 `spikes/sp15_s1.py`를 돌렸다. 이 컨테이너에는 Claude 로그인이 있어 `not_run`이 아니다. 가짜 MCP 도구와 가짜 서브에이전트를 쓴 구조 확인이고, 시간·턴 값은 실제 전문가 호출이 아니라서 노트북 확인 목록 0번(Task 17)에서 같은 스크립트를 한 번 더 돌려 `full*` 줄을 갈음한다. 같은 스크립트를 네 번 돌렸고 모든 판정 줄이 같았다(`tool_result_text`만 검사 방식을 고치기 전 한 번 흔들렸다).

```
agents_ok=True subagent_tool=Agent
x_only_a=True y_only_b=True
tool_result_text=True
deny_hook_ok=True
disallow_main_ok=False
builtin_agent_blocked=True
resume_input_tokens=8587,4440
full6_seconds=12 full6_turns=7
full2_seconds=9 full2_turns=5
```

| 항목 | 값 | 뜻 |
| --- | --- | --- |
| `SUBAGENT_TOOL` | `Agent` | `init`의 도구 목록에는 `Task`로 나오지만 모델이 부르는 `ToolUseBlock`과 `PreToolUse` 훅의 `tool_name`은 `Agent`다. 훅은 둘 다 본다 |
| `agents_ok` | True | `ClaudeAgentOptions.agents`의 `x`·`y`를 모델이 `subagent_type`으로 부른다 |
| `x_only_a`, `y_only_b` | True | 각 서브에이전트 안에서 불린 도구는 자기 도구 하나뿐(`parent_tool_use_id`로 짝지어 확인) |
| `tool_result_text` | True | 본 스레드 `UserMessage`의 `ToolResultBlock`에 서브에이전트 글이 온다. 글은 `[Subagent hand-back] ...` 머리말로 감싸 온다 |
| `deny_hook_ok` | True | 셋째 서브에이전트 호출을 `PreToolUse` 훅이 `permissionDecision: deny`로 거절했고, 거절 글이 `ToolResultBlock`으로 돌아왔다 |
| `disallow_main_ok` | **False** | 본 스레드에 `disallowed_tools=[read_a, read_b]`를 주면 서브에이전트 시작이 `Agent 'x' would be spawned with zero tools ... unrecognized [mcp__planner__read_a]`로 실패한다. 도구 이름이 통째로 빠져 서브에이전트도 못 쓴다 |
| `builtin_agent_blocked` | True | `general-purpose` 호출을 훅이 거절했고 `write_c`는 0번 불렸다 |
| `resume_input_tokens` | 8587,4440 | 둘째가 첫째보다 크게 늘지 않는다(오히려 줄었다). 서브에이전트 원문이 resume 앞머리를 채우지 않는다 |
| `full6_*` | 12초, 7턴 | 서브에이전트 6개. 가짜 도구라 짧다. 600초 한참 아래 |
| `full2_*` | 9초, 5턴 | 서브에이전트 2개 + 본 스레드 읽기 둘 |

본 스레드 옵션은 `build_options()` 결과를 `dataclasses.replace`로 고쳐 `tools=["Agent"]`, `allowed_tools=["Agent", "mcp__planner__*"]`, `agents`, `hooks={"PreToolUse": [HookMatcher(matcher=None, hooks=[gate])]}`를 얹은 모양이다. `tools=[]`이면 `Agent` 도구가 없어 서브에이전트를 부를 수 없으므로 Task 11은 `tools=["Agent"]`로 넘겨야 한다.

## 판정

- `agents_ok`·`x_only_a`·`y_only_b`·`deny_hook_ok`가 모두 True: **안 A 그대로.** 멈추지 않는다.
- `disallow_main_ok=False`: **Task 11에서 `disallowed_tools`를 넘기지 않는다.** 본 스레드도 전문가 읽기 도구를 볼 수 있다(모두 읽기라 받아들인다).
- `builtin_agent_blocked=True`: 멈추지 않는다. Task 11 `SubagentGate`가 `subagent_type`이 전문가 키가 아니면 거절하는 길이 먹는다. 훅은 `permissionDecision: "deny"`를 돌려주면 된다.
- `full6_seconds`(12)는 600 이하라 `brain_timeout_s`를 따로 올리지 않는다. `limits.full_diagnosis`는 `max_turns = 30`, `brain_timeout_s = 900` 그대로. 전체 진단 6명이 실제 읽기를 하면 이 값보다 훨씬 걸리므로 노트북 실행에서 다시 본다.
- 보통 매니저 메시지: `limits.manager_message.max_turns = max(12, ceil(5 × 1.5)) = 12`, `limits.manager_message.brain_timeout_s = max(300, ceil(9 × 1.5)) = 300`. Task 12가 이 값을 `config.toml`에 쓴다.

## 결정 셋

1. `SUBAGENT_TOOL = "Agent"`. 훅 매처는 `Agent`와 `Task` 둘 다 받는다.
2. `disallow_main_ok = False`: `disallowed_tools` 미사용.
3. `builtin_agent_blocked = True`: 훅 거절로 내장 서브에이전트를 막는다.
4. `limits.full_diagnosis`: 30턴·900초 유지. `limits.manager_message`: 12턴·300초 유지.

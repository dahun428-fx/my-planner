## S1 작업 스케줄러에서 SDK 호출 — 성공 (조건부: 창 숨김 필요)

**명령**
- 임시 작업 `\my-planner-spike\s1_*` (트리거 "로그온할 때", Interactive, 제한된 권한)을 만들고 `Start-ScheduledTask`로 즉시 실행. 동작: `pythonw.exe spikes\s1_task.py ...`.
- 스크립트는 SDK `query("안녕이라고만 답해")`를 스펙 5.3 설정으로 부르고, 호출 중 50ms마다 새로 보이는 콘솔 창(`ConsoleWindowClass`, `CASCADIA_HOSTING_WINDOW_CLASS`, `PseudoConsoleWindow`)을 기록.

**출력 요약**

| 변형 | 결과 | 새 콘솔 창 |
|---|---|---|
| pythonw 그대로 | "안녕", 4.8초 | **뜸**: Windows Terminal 창 (제목 `...\_bundled\claude.exe`) |
| pythonw + PATH에서 claude 제거 | "안녕", 4.6초 | 뜸 (같음) |
| pythonw + `AllocConsoleWithOptions(NO_WINDOW)` + PATH 제거 | "안녕", 2.9초 | **없음** (hr=0, result=NEW_CONSOLE) |
| `conhost.exe --headless python.exe` + PATH 제거 | "안녕", 4.8초 | **없음** |

- 원인: SDK가 `anyio.open_process`로 `claude.exe`(콘솔 앱)를 `creationflags` 없이 띄운다. 부모가 콘솔 없는 pythonw이면 자식마다 새 콘솔이 생기고, 기본 터미널이 Windows Terminal이라 창이 보인다. 버전 확인(`claude -v`)과 본 호출, 두 번 뜬다.
- 구독 로그인: `apiKeySource: "none"`, 사용자 구독 로그인으로 호출됨(`ANTHROPIC_API_KEY` 없음).

**CLI 경로 (단계 3)**: SDK `_find_cli()`는 번들 CLI를 먼저 찾는다. PATH를 `C:\WINDOWS\system32;C:\WINDOWS`로 줄여도 번들 CLI로 정상 호출. `cli_path`는 지정하지 않는다. 참고로 사용자 설치 CLI는 `C:\Users\jungdahun\.local\bin\claude.exe` 2.1.289(번들보다 낮음).

**로그아웃 상태 (단계 4)**: 실제 `claude logout`은 하지 않았다(이 원격 세션이 끊김). 대신 `env`에 `CLAUDE_CONFIG_DIR=<빈 임시 폴더>`를 넣어 로그인 정보가 없는 상태로 호출.
- 스트림: `SystemMessage(init)` → `AssistantMessage(error="authentication_failed", text="Not logged in · Please run /login")` → `ResultMessage(subtype="success", is_error=True, terminal_reason="api_error", api_error_status=None, result="Not logged in · Please run /login")`
- 그 뒤 예외: `claude_agent_sdk._errors.ResultError` (`ProcessError` 하위), 메시지 `Claude Code returned an error result: Not logged in · Please run /login (exit code: 1)`, `exit_code=1`, `stderr=None`.
- 소요 1.6초, API 호출 0회. `claude login`으로 되돌릴 필요 없음(실제 로그인은 건드리지 않음). 임시 폴더는 삭제.

**사용 한도 (단계 5)**: 실제 한도 도달은 재현하지 않았다. SDK 0.2.173 소스(`types.py`, `message_parser.py`, `_errors.py`)와 정상 호출의 실제 이벤트로 확인.
- 매 호출마다 `RateLimitEvent`가 온다. 실제 예: `status="allowed", rate_limit_type="five_hour", resets_at=1792780200`(Unix 초), `raw.unifiedWindows.{five_hour,seven_day}.{utilization,resetsAt}`.
- `RateLimitInfo.status`: `allowed` | `allowed_warning` | `rejected`. `rate_limit_type`: `five_hour` | `seven_day` | `seven_day_opus` | `seven_day_sonnet` | `overage`.
- `AssistantMessage.error` 값: `authentication_failed`, `billing_error`, `rate_limit`, `invalid_request`, `server_error`, `unknown`.

### 오류 판별 규칙 (스펙 5.3 `BrainResult.status`)

호출 중 받은 메시지를 모두 보고, 예외(`ResultError`/`ProcessError`)는 잡은 뒤 아래 순서로 판정한다.

1. `AssistantMessage.error == "authentication_failed"` → `auth_error`. (예외가 뒤따라도 이 판정이 우선)
2. `RateLimitEvent.rate_limit_info.status == "rejected"` 또는 `AssistantMessage.error == "rate_limit"` → `rate_limited`. `limited_until`은 `rejected` 이벤트의 `resets_at`(Unix 초 → UTC ISO), 없으면 지금 + 1시간.
3. `AssistantMessage.error == "billing_error"` → `auth_error`와 같이 취급(사용자가 PC에서 계정을 확인해야 함). 스펙에 따로 없으므로 스펙 갱신 대상.
4. `ResultMessage.subtype == "error_max_turns"` 또는 `ResultError.subtype == "error_max_turns"` / `terminal_reason == "max_turns"` → `max_turns`.
5. 그 밖의 예외, `ResultMessage.is_error=True` → `error`.
6. 아니면 `ok`.

- `allowed_warning`은 오류가 아니다(로그만).
- 문자열 매칭(`"Not logged in"`)은 쓰지 않는다. `error` 필드가 있다.
- 한도 도달 시 실제 모양(이벤트 순서, 예외 여부)은 미검증. 위 2번 규칙은 SDK 타입 정의 기반이다.

## S2 도구 잠금 — 성공

**명령**: `spikes\s2_tools.py`, `spikes\s2_read2.py`. 더미 도구 12개(`tool_01`~`tool_12`)를 가진 in-process MCP 서버 `planner`, 스펙 5.3 설정 그대로.

**출력 요약**
- `init.tools`: `mcp__planner__tool_01`~`tool_12` 12개뿐. `ToolSearch`, `Read`, `Bash` 등 기본 도구 없음. `mcp_servers`: `planner`(sdk, connected)만.
- "사용 가능한 도구를 전부 나열해" → 12개만 나열.
- "Read 도구로 `C:\Windows\win.ini`를 읽어" → "Read 도구가 없어 읽지 못했다"고 답함. 도구 호출 0회, `permission_denials` 없음.
  - 첫 시도("다른 어떤 방법이라도 써서")는 응답이 안전 분류기에 막혔다가 같은 결론. 계획 문구 그대로 다시 해서 깨끗한 결과를 얻음.
- 12개 모두 호출: 문자열 `prompt`로 12/12 호출, 13턴. `ClaudeSDKClient`로도 12/12. 지연 로드(ToolSearch) 없이 바로 호출됨.

**정한 값**
- (a) 문자열 `prompt`로 동작한다. 스트리밍 입력 불필요. 단, 12개 호출에 13턴이 들었으므로 `max_turns=10`이면 한 호출에서 도구를 9번 넘게 부를 수 없다(스펙대로 두되 인지).
- (b) `strict_mcp_config=True` 필드. `_build_command()` 출력에 `--strict-mcp-config`, `--tools ""`, `--setting-sources=`, `--permission-mode dontAsk`, `--input-format stream-json` 확인.

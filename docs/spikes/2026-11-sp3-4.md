## S7 한 루프의 aiohttp, 폴링, tick, 두뇌 — 클라우드 성공, 기기 노트북 대기

**클라우드 시험**: `spikes/s7_loop.py`. 한 이벤트 루프에 `AppRunner(access_log=None)` + `TCPSite("127.0.0.1", 8787)`, 가짜 롱폴링 태스크(30초 sleep 반복), 10초 tick 태스크(안에서 5초짜리 가짜 두뇌 `await asyncio.sleep(5)`)를 같이 돌렸다.

```bash
.venv/bin/python spikes/s7_loop.py 30 &
for i in $(seq 10); do curl -s -o /dev/null -w "%{time_total}\n" http://127.0.0.1:8787/ping; sleep 1.5; done
```

**출력 요약**: 10회 모두 0.0009~0.0032초(기준 0.1초 미만). 가짜 두뇌가 도는 동안에도 같음. tick 로그 정상.
- 주의: 이 컨테이너는 Linux라 루프가 `_UnixSelectorEventLoop`였다. Windows Proactor에서의 동작은 아래 노트북 단계에서 본다.

**노트북 대기 (`needs-laptop`)**: 같은 파일을 노트북 작업 폴더 `spikes\s7_loop.py`에 쓴다(`spikes/s7_loop.py`의 내용에 아래 두 가지를 더한다: 시작 시 `type(asyncio.get_running_loop())` 이름을 파일로 기록, 그리고 5초 가짜 두뇌 대신 Agent SDK `query("안녕이라고만 답해", options=SP1 5.3 설정)` 호출).
1. 작업 스케줄러에 임시 작업 `\my-planner-spike\s7_loop`을 만든다(동작 `E:\my-planner\.venv\Scripts\pythonw.exe spikes\s7_loop.py 60`, 로그온 트리거, Interactive). `Start-ScheduledTask`로 실행하고 SP1 `s1_task.py`처럼 50ms마다 새 콘솔 창을 센다(`AllocConsoleWithOptions(NO_WINDOW)`를 시작에 호출).
2. 기록된 루프 이름이 `ProactorEventLoop`인지 확인한다.
3. 실행 중 `curl -s -o /dev/null -w "%{time_total}\n" http://127.0.0.1:8787/ping`을 10회, 그리고 SDK `query(...)`가 도는 동안에도 10회. 모두 0.1초 미만, 콘솔 창 0개여야 한다.
4. 실패면 스펙 3장 S7 대안(API만 별도 스레드 루프, `run_coroutine_threadsafe`)으로 4.3과 티켓 01 `start_api`를 고친다. 끝나면 임시 작업을 지운다.

## S8 SSE 조각 도착 — 클라우드 성공, 기기 노트북 대기

**클라우드 시험**: `spikes/s8_sse.py`. 200ms 간격 `text-delta` 20개, 헤더 `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`. `ts`(moreutils)가 없어 대체 명령을 썼다.

```bash
curl -N -s -D - http://127.0.0.1:8787/sse | python3 -u -c "import sys,time;t=time.time();[print(f'{time.time()-t:.3f}',l,end='') for l in sys.stdin]"
```

**출력 요약**: 첫 조각 0.000초, 이후 0.198, 0.399, 0.599, 0.800, … 3.810초(간격 ≈ 0.2초, 20개 모두 조각마다 도착). 헤더 `X-Accel-Buffering: no` 확인.

**노트북 대기 (`needs-laptop`)**
1. tailnet 관리 화면에서 MagicDNS와 HTTPS 인증서를 켠다.
2. 노트북에서 `spikes\s8_sse.py`(위와 같은 내용, 대기 시간 인자 300)를 돌린다.
3. `tailscale serve --bg --https=443 http://127.0.0.1:8787`.
4. 폰(셀룰러 + Tailscale)과 노트북 브라우저에서 `https://<기계>.<tailnet>.ts.net/sse`에 `fetch` + `ReadableStream`으로 조각마다 도착 시각을 재서 첫 조각 지연과 간격을 기록한다.
5. 묶여 오면 스펙 3장 S8 대안(15초 간격 SSE 주석 줄)을 시험한다. 끝나면 `tailscale serve reset`.

## S9 사설망 접근(PNA) 사전 요청 — 클라우드 성공, 기기 노트북 대기

**클라우드 시험**: `spikes/s9_cors.py`. 허용 출처 목록(`https://example.vercel.app`)을 가진 aiohttp 미들웨어. 허용 목록은 스펙 14장대로 정확 일치이며 `*.vercel.app` 전체가 아니다.

```bash
curl -si -X OPTIONS -H "Origin: https://example.vercel.app" -H "Access-Control-Request-Method: GET" -H "Access-Control-Request-Private-Network: true" http://127.0.0.1:8787/api/v1/health
```

**출력 요약**: `204 No Content`, `Access-Control-Allow-Origin: https://example.vercel.app`, `Access-Control-Allow-Methods: GET, POST, PUT, DELETE`, `Access-Control-Allow-Headers: Authorization, Content-Type`, `Access-Control-Allow-Private-Network: true`, `Vary: Origin`.
- 허용 밖 출처(`https://evil.vercel.app`)는 `204`에 CORS 헤더가 하나도 없다(스펙 14장 일치).

**노트북 대기 (`needs-laptop`)**
1. 노트북에서 `spikes\s9_cors.py`를 허용 출처에 Vercel 미리보기 주소를 넣고 돌린다. `tailscale serve`로 HTTPS 노출.
2. Vercel에 시험 페이지(정적 HTML 한 장, `fetch(<ts.net 주소>/api/v1/health)`)를 미리보기로 올린다.
3. 데스크톱 Chrome, Android Chrome, iOS Safari에서 열어 `fetch` 성공 여부와 권한 창이 뜨는지, 뜨면 문구 그대로를 기록한다(사용자 안내 문서, 티켓 19에 쓴다).

## S10 웹 푸시 — 클라우드 성공, 기기 노트북 대기

**클라우드 시험**: `spikes/s10_push.py`. 로컬 aiohttp 가짜 푸시 서버(`/push/201`, `/push/404`, `/push/410`이 각 상태 코드로 답함). 수신자 P-256 키와 auth 비밀을 만들어 구독을 꾸미고, `pywebpush.webpush(..., vapid_private_key=Vapid(), ttl=3600, headers={"Topic": "run-1"})`로 보낸 뒤 본문을 `http_ece.decrypt(..., version="aes128gcm")`으로 풀었다. 메시지는 꾸며 낸 내용.

```bash
.venv/bin/python spikes/s10_push.py
```

**출력 요약**

| 상태 | `webpush()` 결과 | 헤더 | 풀어 낸 본문 = 원문 |
|---|---|---|---|
| 201 | 반환, `status_code` 201 | `ttl: 3600`, `topic: run-1`, `Content-Encoding: aes128gcm`, `Authorization: vapid t=...` | 같음 |
| 404 | `WebPushException`, `e.response.status_code` 404 | 같음 | 같음 |
| 410 | `WebPushException`, `e.response.status_code` 410 | 같음 | 같음 |

- 404/410은 예외의 `response.status_code`로 판별한다(D4: 404/410이면 구독을 끈다).
- `webpush()`는 동기 호출이므로 `asyncio.to_thread`로 감싼다.
- 서버가 받은 `Authorization`은 `vapid t=<JWT>,k=<공개키>` 형식.

**노트북 대기 (`needs-laptop`)**
1. Windows `.venv`에 `pip install pywebpush==2.5.0 aiohttp==3.14.5`가 설치되고 `spikes\s10_push.py`가 같은 결과를 내는지 확인한다.
2. 실제 수신 시험: 정적 시험 페이지(Vercel 미리보기, 서비스 워커 `push` 이벤트로 `showNotification`)에서 `PushManager.subscribe({userVisibleOnly: true, applicationServerKey: <VAPID 공개키>})`로 구독을 받아 노트북에서 `webpush()`로 보낸다. 대상: Android Chrome, iPhone 홈 화면 PWA(iOS 16.4 이상). 수신 여부와 지연을 기록한다.
3. iOS 구독이 안 되면 스펙 3장 S10 대안(D4 처리)을 따른다.

## S11 Agent SDK 글 조각과 가르기 — 노트북 대기

이 클라우드 컨테이너에는 `claude` CLI는 있지만 구독 로그인이 없어 시험하지 않았다.

**노트북에서 만들 `spikes\s11_stream.py`**(SP1 `s1_task.py`, `s2_tools.py`와 같은 SDK 설정 5.3 블록 사용: `strict_mcp_config=True`, `setting_sources=[]`, `permission_mode="dontAsk"`, 도구 잠금, `max_turns=10`)
1. `ClaudeAgentOptions(..., include_partial_messages=True)`로 `query("1부터 5까지 한 줄로 세어줘")`. 모든 메시지를 훑는다.
2. `StreamEvent`의 필드 경로를 기록한다(예상: `event["type"] == "content_block_delta"`, `event["delta"]["type"] == "text_delta"`, `event["delta"]["text"]`, `event["index"]`). `content_block_start`/`content_block_stop`도 기록한다. 글 조각을 이어 붙인 문자열이 `ResultMessage.result`와 같은지 비교한다.
3. 가르기: 첫 호출에서 "비밀 단어는 바나나. 기억해"라고 말하고 `session_id`를 받는다(`ResultMessage.session_id`). 둘째 호출을 `resume=<id>, fork_session=True`로 "비밀 단어가 뭐였지?" → 새 `session_id`가 다르고 "바나나"라고 답하는지. 셋째로 갈라진 쪽에서 "두 번째 단어는 사과"라고 말한 뒤, 원래 세션을 `resume=<원래 id>`로 다시 열어 "두 번째 단어가 있나?"라고 물어 모른다고 답하는지.
4. 기록할 것: `StreamEvent` 필드 경로, `fork_session`이 새 `session_id`를 주는 시점(`SystemMessage(init)`인지 `ResultMessage`인지), 원문 기록 파일이 새 id로 생기는지.
5. 실패면 스펙 3장 S11 대안(답 전체를 `text-delta` 하나로, 가르기는 SP1 resume 실패 대체 경로)이 티켓 06·07의 기본이다.

**클라우드에서 한 일(티켓 06b)**: `StreamEvent` 필드 경로(`event.type`, `content_block.type == "text"`, `delta.type == "text_delta"`, `delta.text`, `index`)는 설치된 SDK 소스(`claude_agent_sdk/types.py`의 `StreamEvent.event`: 원본 Anthropic 스트리밍 이벤트 dict)에서 가져왔고, **노트북에서 실제로 확인하기 전까지는 미확인**이다. 경로는 `harness/brain.py`의 `text_block_event` 한 함수에만 있어 위 2단계 결과대로 고치면 된다. 조각이 하나도 오지 않으면 06처럼 끝난 뒤 글 블록 하나로 보낸다(같은 글은 두 번 보내지 않는다).

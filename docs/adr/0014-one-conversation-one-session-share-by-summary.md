# 대화 하나는 두뇌 세션 하나이고, 세션끼리는 원문이 아니라 공유 상태와 요약으로만 잇는다

Dahun은 채팅을 대화별로 나눠 다시 찾고 싶어 하고, 두뇌가 지난 대화를 전부 읽지 않기를 바란다. 나중에 AI 서브에이전트를 여러 개 둘 때를 대비한 구조이기도 하다. 그래서 대화 하나 = 두뇌 세션 하나로 고정하고, 새 세션은 앞머리(할 일, 스케줄, 습관, 컨디션 같은 DB의 공유 상태)로만 시작한다. 대화가 닫히면 짧은 제목과 요약을 DB에 남기고, 두뇌는 필요할 때만 `find_conversations`로 요약을 꺼낸다(원문은 주지 않는다). 긴 대화는 사용자 메시지 30개마다 요약 + 최근 몇 줄로 새 세션을 시작한다(말아 넣기). 최근 요약을 늘 붙이는 안은 쓰지 않는 컨텍스트가 매번 들어 버렸다. 앞으로 붙일 서브에이전트도 같은 규칙을 따른다: 자기 세션을 갖고, 서로의 원문을 읽지 않으며, DB와 요약으로만 정보를 나눈다. 상세는 [SP9 스펙](../superpowers/specs/2026-10-25-sp9-app-tabs-memo-schedule-design.md) 4.2, 7장.

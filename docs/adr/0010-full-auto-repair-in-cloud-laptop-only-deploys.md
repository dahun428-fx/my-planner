# 자동 복구는 클라우드가 고쳐 머지하고, 노트북은 CI 통과 커밋만 배포·롤백한다

Dahun은 BE·운영 앱·대시보드에서 장애가 나면 사람 없이 고쳐지기를 원한다(2026-10-24, 완전 자동, 금지선 없음). 고치는 Claude는 노트북이 아니라 GitHub Actions의 Claude Code 액션에서 돈다. 코드를 고치는 강한 권한의 에이전트를 비서가 도는 노트북 밖에 두려는 것이다. BE는 tailnet 안에만 열려 있어서, 감지는 노트북의 별도 작업 medic(표준 라이브러리만 쓰고 Claude를 부르지 않는 결정적 코드)이 하고 가린 장애 리포트를 GitHub 이슈로 올린다. 노트북 전체가 멈춘 경우는 medic의 GitHub 하트비트가 끊기는 것으로 Actions가 알아채 텔레그램으로 알린다. 노트북은 CI가 성공한 `main` 커밋만 받고, 배포 직전 DB를 백업하고, 배포 뒤 확인이 실패하면 코드를 되돌리며 스키마가 바뀐 배포면 DB도 되돌린다. 머지는 Claude가 아니라 CI 성공을 확인한 셸 단계가 한다.

다른 결정과의 관계: ADR 0007(BE 단일 쓰기 주체)의 예외는 배포 롤백 때 BE를 끈 채 `planner.db` 파일을 백업으로 바꾸는 것 하나다. ADR 0001(구독 로그인)은 같은 계정의 구독 토큰을 저장소 시크릿에도 두는 것으로 넓어진다. 구독 토큰으로 안 되면 수리만 API 키로 바꾼다.

대가: 금지선이 없어서 수리가 테스트나 인증을 느슨하게 할 수 있고, 막는 것은 CI·리뷰 에이전트·횟수 한도·끄는 스위치뿐이다. 스키마가 바뀐 배포를 되돌리면 배포 뒤 몇 분간 쓴 할 일·컨디션이 사라진다. GitHub에는 허용 목록의 진단 정보만 올라가므로 원본 데이터는 노트북에 남는다(P5, 예외 한 줄 추가). 상세는 [SP6 스펙](../superpowers/specs/2026-10-24-sp6-auto-recovery-design.md).

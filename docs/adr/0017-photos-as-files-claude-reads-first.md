# 0017. 사진은 DB 밖의 파일로 남기고, 처음엔 두뇌(Claude)가 읽는다

- 날짜: 2026-10-26
- 상태: 제안 (Dahun 방향 결정 D1~D3, 세부는 SP10 스펙 15장 확인 전)

Dahun은 메모나 채팅에 사진을 올리면 비서가 알아서 기록하고, 사진도 남기길 원한다.

**저장.** 사진 바이트는 `data/photos/`에 파일로 한 번 쓰고 바꾸지 않는다. `planner.db`에는 사진마다 경로·해시·크기와 메모·메시지 연결만 둔다. DB에 BLOB으로 넣으면 매일 백업(14개)마다 모든 사진이 다시 복사되고, 배포 롤백(ADR 0010)이 DB 파일을 통째로 바꿀 때 사진도 함께 되돌아간다. 쓰기는 지금처럼 BE 한 곳, 즉시 갈래에서 한다(ADR 0007). 파일 지우기는 하루 한 번 작업만 한다.

**읽기.** 사진 읽기는 BE 안의 자리 하나(`PhotoReader`)를 거친다. 처음 구현은 두뇌의 도구 없는 한 번 호출(구독 Claude, ADR 0001)이고, 채팅 사진은 두뇌가 직접 보고 기존 도구로 기록한다. 로컬 OCR 리서치(`E:\ocr-local-benchmark`)는 휴대폰 사진·손글씨를 재 보지 않았고 CPU 시간이 길어, 기능을 그것에 묶지 않는다. 온프레미스 OCR은 부가 서비스(ADR 0016, SP11)로 키워 같은 자리에 끼운다.

대가: 사진 내용이 두뇌 호출로 Anthropic에 간다(채팅 글과 같은 경로, 원본 저장은 노트북뿐, 마스터 P5). SDK 세션 파일에 이미지가 남을 수 있다. 사진 파일은 DB 백업에 들지 않아, 배포 롤백 뒤 몇 분간 올린 사진은 연결이 사라지고 7일 뒤 지워진다. 디스크 고장 대비 백업은 없다. 상세는 [SP10 스펙](../superpowers/specs/2026-10-26-sp10-photos-claude-reads-design.md).

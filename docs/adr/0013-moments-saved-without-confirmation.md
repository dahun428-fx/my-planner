# 이룬 순간은 확인 없이 저장하고, 숨기기·지우기로 되돌린다

SP3-4는 비서가 만든 삶의 기록(사건, 챕터)을 초안으로만 내고 사용자가 버튼을 눌러야 저장하게 했다. SP8의 **이룬 순간**은 이 규칙을 따르지 않는다: 하루가 끝나면 비서가 그날 끝낸 할 일, 습관 체크, 사용자 메시지에서 0~3줄을 뽑아 묻지 않고 바로 `status_moments`에 저장한다. Dahun이 "그냥 백그라운드에서 AI가 알아서 정리하게"를 골랐고(2026-10-25 결정 카드), 날마다 확인 버튼이 붙으면 누를 거리가 쌓여 P1(한 번에 하나)·P2(밀린 것 없음)에 걸리기 때문이다.

확인을 빼도 되는 까닭은 순간이 가벼운 층이기 때문이다. 순간은 곡선의 사건이 아니고, 경험치·칭호·스탯을 주지 않으며(근거인 할 일·습관이 이미 경험치를 받았다, ADR 0006), 사용자가 이미 남긴 데이터를 요약할 뿐이다. 그 대신 지킬 것:

1. 사용자는 운영 앱 상태창에서 어느 순간이든 숨기거나(되돌릴 수 있음) 지울 수 있다.
2. 순간은 사건이 되지 않는다. 사건이 되려면 지금처럼 두뇌가 묻고 초안 + 버튼을 거친다.
3. 하루 끝 작업의 두뇌에는 `save_moments` 도구 하나만 준다(코드로 거른다, ADR 0005).
4. 순간의 글은 SQLite에만 둔다. 로그, md 내보내기(ADR 0003의 예외), 원문 기록, 활동 기록 `summary`, 웹 푸시에 내보내지 않는다. 순간을 만드는 호출은 Agent SDK 세션을 저장하지 않는다(`no-session-persistence`).
5. 순간은 운영 앱과 대시보드에서만 보인다. 텔레그램은 은퇴할 예정이고 새 기능은 앱 전용이라(Dahun, 2026-10-25), 텔레그램 통로의 두뇌(대화, 회차, 회고 앞머리)와 텔레그램 `/status`는 날짜와 개수만 받는다.
6. 알림을 보내지 않는다.

받아들이는 것: 앱 대화에서 두뇌가 `get_status`로 순간의 글을 읽으면, 그 결과는 그 대화의 SDK 세션 파일(`~/.claude/projects/`, 대화 이어 쓰기용, SP1)에 다른 대화 내용과 함께 남는다. 노트북 안의 사본이고 대화 기록과 같은 취급이다.

사건·챕터·할 일 초안의 확인 규칙은 바뀌지 않는다. 상세는 [SP8 스펙](../superpowers/specs/2026-10-25-sp8-status-records-history-design.md) 6장.

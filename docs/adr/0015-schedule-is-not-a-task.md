# 시간이 정해진 일은 할 일이 아니라 스케줄 표에 두고, 반복 일정의 날짜는 읽을 때 펼친다

할 일은 "언젠가 끝낼 일"이고 스케줄은 "그 시간에 있는 일"이다(Dahun Q1). 할 일의 `scheduled_at`에 반복과 알림을 더하면 끝내기·밀림·우선순위 규칙이 일정에 맞지 않고, 반복 날짜가 열린 할 일로 쌓인다(ADR 0011이 피한 것). 그래서 `events`(정의와 반복 규칙)와 `event_skips`(건너뛴 날)만 두고 날짜별 일정은 읽을 때 펼친다. 알림을 보냈는지는 `event_reminders`에 날짜마다 남겨 두 번 보내지 않는다. 열린 할 일의 시각은 스케줄로 옮기고, 이후 할 일에는 시각을 붙이지 않는다. 상세는 [SP9 스펙](../superpowers/specs/2026-10-25-sp9-app-tabs-memo-schedule-design.md) 4.1, 5장.

덧붙임 (2026-10-26, SP9b): 일정 정리 알림은 일정 알림과 같은 통로와 규칙(두뇌 없음, 멈춤 중에도 보냄, 비서가 먼저 거는 말의 상한에 세지 않음)을 쓴다. 다만 사용자가 일정마다 고른 시각이 아니라 비서가 모아 보내는 알림이고, 기본 켜짐이라 하루 연락이 기본 두 번이라는 P1의 예외다. Dahun이 2026-10-25에 직접 요청했고(결정 카드 C), 일정이 없는 날은 보내지 않으며, 종류마다 끌 수 있다. 상세는 [SP9b 스펙](../superpowers/specs/2026-10-26-sp9b-schedule-digests-design.md).

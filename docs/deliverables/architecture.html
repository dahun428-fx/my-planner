서버 없이 노트북에서 도는 단일 프로세스이고, 두뇌가 할 수 있는 일은 planner 도구로 좁혀 두었습니다.

  • 바깥 연결은 두 곳뿐입니다: 텔레그램 Bot API(롱폴링)와 Anthropic(Dahun의 구독 로그인). 웹훅이나 공개 주소는 없습니다.
  • 원본 데이터는 노트북의 state/planner.db(SQLite)와 data/(md)에만 있고, 클라우드 백업은 하지 않습니다.
  • 상시 실행은 Windows 작업 스케줄러가 맡습니다. 프로세스가 죽으면 5분 워치독 트리거가 다시 띄웁니다(S6).
  • main(0336f4d)에 티켓 SP1-00~14와 최종 리뷰 수정(#35)이 모두 들어 있습니다. 이 문서의 구성 요소는 전부 구현되었고, 남은 것은 노트북 점검(#16)과 7일 수용 테스트(#17)입니다.
  • 받은 메시지는 답하기 전에 inbound_pending에 먼저 저장하고, 두뇌 호출 한 번은 300초를 넘지 않으며, 답 전송은 3번(1초·2초 간격)까지 해 봅니다. 그래서 강제 종료나 깨어난 직후의 끊긴 연결에도 메시지가 사라지거나 비서가 멈추지 않습니다.

1C4 표기와 구현 상태

C4 모델은 지도처럼 축척을 바꿔 가며 봅니다. L1은 바깥 세계, L2는 실행 단위와 저장소, L3는 코드 모듈입니다.

범례 · C4 표기 (이 문서의 모든 구조도에 적용)
  • 사람 (Person)짙은 청록 타원. 이 시스템의 사용자는 Dahun 한 사람
  • 소프트웨어 시스템청록으로 채운 상자. 우리가 만드는 my-planner
  • 컨테이너옅은 청록 상자. 따로 실행되거나 저장되는 단위(프로세스 안 작업, DB, 폴더)
  • 컴포넌트흰 상자 + 청록 실선. 파이썬 모듈 하나
  • 외부 시스템흰 상자 + 회색 잔 점선. 우리가 만들지 않는 것
  • 예정 (SP1-NN)청록 긴 점선. main에 아직 없는 부분. SP1 구성 요소는 모두 구현되어 이 판의 그림에는 없습니다(작업 스케줄러 작업은 노트북 등록 전이라 이 선으로 그림)
  • 관계화살표 위 글자 = 무엇을 어떻게 주고받는지
  • 경계회색 틀 = 노트북, 프로세스 같은 실행 경계
구현됨 · main 처음부터 있던 것(SP1-01·02) 구현됨 · SP1-05 그 티켓에서 들어온 것 구현됨 · #35 최종 리뷰 수정에서 들어온 것

구현 상태는 2026-10-23 main 0336f4d(티켓 SP1-00~14 PR #18~#34, 최종 리뷰 수정 #35, 문서 동기화 #36)의 코드를 직접 읽어 확인했습니다. 알약의 티켓 번호는 그 부분이 들어온 PR입니다.

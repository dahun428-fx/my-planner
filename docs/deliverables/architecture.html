노트북 BE 하나와 화면 세 개: 전체 시스템의 구조와 경계

비서의 판단, 데이터, 규칙은 노트북의 BE 프로세스 한 곳에 있습니다. 텔레그램, 아이폰 운영 앱, 웹 대시보드는 같은 BE를 보는 창입니다. 이 문서는 C4 모델로 바깥 세계부터 파이썬 패키지까지 차례로 확대해 보여 줍니다.

한눈에 보기

BE는 노트북 한 대의 파이썬 프로세스 하나이고, 데이터를 바꾸는 길은 그 안의 Dispatcher 하나뿐입니다.

  • BE 프로세스 안에 텔레그램 봇, 1분 tick 루프, 하네스와 두뇌, 도구(MCP), HTTP API, 웹 푸시가 같은 asyncio 루프로 돕니다(ADR 0007).
  • 운영 앱과 대시보드는 Vercel에서 받은 정적 화면입니다. 데이터는 Vercel을 거치지 않고, 브라우저가 tailnet으로 BE의 /api/v1을 직접 부릅니다(ADR 0008, 0009).
  • BE는 127.0.0.1:8787에만 열고, 바깥에서는 tailscale serve로만 닿습니다. Funnel(공개 인터넷)은 쓰지 않습니다.
  • 원본 데이터는 노트북의 state/planner.db(SQLite, 마이그레이션 001~012)와 data/(md)에만 있습니다.
  • 감시자 medic과 GitHub Actions의 자동 수리(SP6 자동 복구)는 기준 커밋 722d0d6에 코드가 없습니다. 그 뒤 SP6-01~05(#136 · #137 · #138 · #140 · #143)가 main에 들어왔습니다(기준 뒤 병합). 그림에서는 점선으로 그렸습니다.

1표기와 읽는 법

C4 모델은 지도처럼 축척을 바꿔 가며 봅니다. L1은 바깥 세계, L2는 따로 실행되거나 저장되는 단위, L3는 BE 안의 파이썬 패키지입니다.

비밀값없음. 토큰과 BE 주소는 빌드, Vercel 환경 변수, 저장소에 넣지 않고 기기마다 사용자가 넣습니다.
배포main 푸시마다 자동. 운영 앱은 web/app/이 바뀌었을 때만 빌드합니다(ignoreCommand).

2시험 접근

티켓마다 TDD로 만들고, 계획에서 합의한 10개 경계에서만 테스트를 씁니다.

  1. TDD, 한 번에 한 조각조각(slice)마다 테스트 하나를 쓰고 → 돌려서 실패(RED)를 보고 → 통과할 만큼만 구현하고 → 다시 돌려 통과(GREEN)를 봅니다. 테스트를 몰아서 먼저 쓰지 않습니다. 티켓이 끝나면 pytest -q 전체가 0 failed여야 합니다.
  2. 10개 시험 경계아래 표의 경계에서만 테스트를 씁니다(2026-10-23 Dahun 합의). 시간이 걸리는 동작(typing 5초, 백오프 2·4·8초, 전송 재시도 1·2초, 재전송 5분, 두뇌 호출 300초 상한)은 실제로 기다리지 않고 가짜 sleep과 FakeClock으로 돌립니다.
  3. 저장소는 직접 시험하지 않음*Repo 클래스는 따로 테스트하지 않고 위 경계를 거쳐 확인합니다. 예외는 마이그레이션 테스트(test_migrations.py)입니다.
  4. RED를 못 볼 때는 변이 확인한 조각에서 구현이 먼저 들어가 테스트가 처음부터 통과한 경우(티켓 01, 04, 08 일부, 티켓 03 전반), 코드를 일부러 망가뜨려 테스트가 실패하는지 본 뒤 되돌렸습니다(mutation check). 티켓 03은 리뷰어가 변이를 직접 넣어 보았고, 살아남은 변이 6개를 테스트 보강으로 잡았습니다.
  5. 티켓마다 코드 리뷰리뷰어가 Critical·Important·Minor로 지적하고, 고친 뒤 재리뷰에서 Approved를 받아야 병합합니다(6절).

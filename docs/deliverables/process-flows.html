1읽는 법과 BPMN 범례

BPMN 2.0은 업무 흐름을 그리는 국제 표준 표기입니다. 아래 기호를 한 번 익히면 모든 그림을 읽을 수 있습니다. 그림마다 아래에 범례 띠와 결론 한 줄이 있고, 분홍 번호는 단계표의 번호와 같습니다.

범례 · BPMN 2.0 기호
  • 시작 이벤트흐름이 시작되는 곳. 가는 선의 원
  • 타이머 이벤트정해진 시각이나 기간이 되면 일어남. 이중 원 안의 시계
  • 메시지 이벤트다른 풀에서 온 메시지. 원 안의 봉투
  • 작업누군가 하는 일 한 단계. 둥근 사각형. 사람이 하는 일은 색을 넣고 왼쪽 위에 사람 표시
  • 배타 게이트웨이조건에 따라 길이 하나만 선택됨. ×가 든 마름모, 화살표에 조건
  • 종료 이벤트흐름이 끝나는 곳. 굵은 선의 원
  • 시퀀스 흐름같은 풀 안의 순서. 실선 화살표. 굵은 선이 정상 경로, 주황 선이 예외 경로
  • 메시지 흐름풀과 풀 사이 전달. 작은 원에서 시작하는 점선, 열린 화살촉
  • 풀 / 레인누가 하는지 나눈 칸. 왼쪽 세로 띠에 이름. 레인 없이 이름만 있는 풀은 속을 그리지 않는 바깥 참여자

예외와 특수 경우

  • 전송이 바로 3회(사이 1초, 2초) 모두 안 되면 failed로 두고 5분 뒤 전송만 한 번 더 한다. 두뇌는 다시 부르지 않는다. 사용자에게 알리지 않는다.
  • 두뇌가 error이고 도구 이벤트가 0개면 한 번 다시 실행한다. 도구 이벤트가 있으면 failed(중복 쓰기 방지).
  • auth_error는 skipped(auth), rate_limited는 skipped(rate_limit). 고정 안내는 하루 한 번(한도는 구간당 한 번)이다.
  • 어제 컨디션 기록이 없고 어제 저녁 체크인이 done이 아니면, 아침 브리핑에 어제 날짜 컨디션 버튼을 붙인다.
  • 컨디션이 2 이하면 비서가 할 일을 줄이자고 먼저 제안한다(시스템 프롬프트 원칙 4).
  • 일요일 저녁 체크인은 주간 회고와 하나로 합쳐 보낸다(프로세스 3).

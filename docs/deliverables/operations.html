my-planner 설치와 운영 안내

Dahun이 노트북에 비서를 설치하고, 매일 쓰고, 문제가 생겼을 때 스스로 고칠 수 있도록 순서대로 적었습니다. 명령은 PowerShell에서 저장소 폴더(E:\my-planner)에 있다고 보고 씁니다.

  • 설치는 네 단계입니다: 폴더와 Python 준비 → 텔레그램 봇 만들기 → .env 채우기 → 작업 등록과 점검.
  • 비서는 하루에 먼저 최대 3번 연락합니다(아침 브리핑, 저녁 체크인, 일요일엔 회고를 저녁에 합침). 노트북이 꺼져 있었으면 켜진 뒤 알맞게 따라잡습니다.
  • 문제가 생기면 비서가 텔레그램으로 고정 안내를 한 번 보냅니다. 안내 문구별로 할 일이 알림 대응과 문제 해결 표에 있습니다.
  • 봇 토큰은 비밀번호입니다. .env 파일에만 적고 어떤 채팅에도 붙여 넣지 않습니다.

2처음 설치

처음 한 번만 합니다. 그림의 순서대로 아래 단계를 따라갑니다.

범례 · BPMN 기호 (flowchart로 근사)
시작 이벤트 (원) 작업 (사각형) 배타 게이트웨이 (마름모) 종료 이벤트 (굵은 원) 시퀀스 흐름

2.1 폴더와 Python

cd E:\my-planner
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.lock
.venv\Scripts\python.exe -m pip install -e . --no-deps

requirements.lock은 정확한 버전 목록입니다. 의존성 범위는 pyproject.toml에 있습니다.

2.2 텔레그램 봇 만들기 (BotFather)

  1. BotFather 찾기텔레그램에서 @BotFather를 찾아 대화를 시작합니다.
  2. /newbot 보내기봇 이름과 사용자명을 정합니다. 사용자명은 ..._bot으로 끝나야 합니다.
  3. 토큰 받기BotFather가 알려 주는 토큰(123456789:ABC... 형식)을 다음 단계의 .env에 넣습니다.
  4. 본인 숫자 ID 확인@userinfobot에게 아무 메시지나 보내고, 답장의 숫자 Id를 적어 둡니다. 사용자명(@...)이 아니라 숫자입니다. 비서는 이 ID의 개인 채팅에만 답하고, 다른 사람이나 그룹 채팅은 무시합니다.
  5. 내 봇에서 시작 누르기만든 봇과의 대화창을 열어 시작(/start)을 한 번 누릅니다. 봇은 먼저 대화를 연 사람에게만 메시지를 보낼 수 있습니다.

2.3 .env 만들기

copy .env.example .env
notepad .env

메모장에서 두 줄을 채우고 저장합니다. .env는 Git에 들어가지 않습니다. config.toml에는 개인값을 넣지 않습니다(넣으면 비서가 시작하지 않습니다).

TELEGRAM_BOT_TOKEN=...
OWNER_TELEGRAM_ID=...
토큰은 어떤 채팅에도 붙여 넣지 않습니다봇 토큰은 비밀번호와 같습니다. 텔레그램 대화, Claude나 다른 AI와의 채팅, 메신저, 이슈, 메모 앱 어디에도 붙여 넣지 말고 E:\my-planner\.env에만 적습니다. 새어 나갔다고 생각되면 BotFather에서 /revoke로 바꾸고 .env를 고친 뒤 비서를 다시 시작합니다. 등록·점검 스크립트는 .env를 읽지도, 비밀값을 출력하지도 않습니다.

2.4 콘솔에서 시험 실행

.venv\Scripts\python.exe -m my_planner
  • 텔레그램에서 봇에게 “안녕”이라고 보내면 답이 옵니다.
  • 끄려면 이 콘솔 창에서 Ctrl+C를 누릅니다. 진행 중인 답은 최대 30초 기다렸다가 끝냅니다.
  • 이미 실행 중이면 새로 띄운 프로세스는 바로 끝납니다(단일 실행 잠금 state\my-planner.lock).
  • 다른 폴더의 데이터를 쓰려면 환경변수 MY_PLANNER_ROOT에 저장소 루트를 지정합니다.

3작업 스케줄러 등록과 점검

콘솔 없이 늘 돌게 합니다. 관리자 권한은 필요 없습니다.

등록 전에 콘솔 비서를 끕니다콘솔에서 python -m my_planner로 띄워 둔 비서가 있으면 먼저 Ctrl+C로 끕니다. 켜 둔 채 등록하면 작업이 띄운 프로세스가 단일 실행 잠금 때문에 바로 끝나고, 점검에서 State is Running이 FAIL로 나옵니다.

등록

powershell -ExecutionPolicy Bypass -File scripts\register_task.ps1
등록되는 작업 두 개
작업언제 도나하는 일
my-planner로그온할 때, 절전에서 깨어날 때, 그리고 5분마다(워치독)pythonw -m my_planner를 띄웁니다. 이미 실행 중이면 아무 일도 하지 않아 중복으로 뜨지 않습니다. 프로세스가 죽으면 5분 안에 워치독이 다시 띄웁니다. 배터리에서도 돌고 시간 제한이 없습니다.
my-planner-wake회차 시각 5분 전 (기본값: 평일 08:55 · 17:25, 주말 09:55 · 17:55)노트북을 절전에서 깨웁니다. 하는 일은 없습니다(pythonw -c pass). 시각은 config.toml에서 계산합니다.
  • 저장소가 다른 폴더에 있으면 -Root D:\my-planner, 깨우기 작업 없이 등록하려면 -NoWake를 붙입니다.
  • 등록한 XML은 state\tasks\에 남습니다. 스크립트는 끝에 my-planner 작업을 한 번 시작하고 “시작했습니다”라고 출력합니다.
  • 회차 시각을 바꾸면 등록 스크립트를 다시 실행합니다. 깨우기 시각이 따라 바뀝니다.

점검

powershell -ExecutionPolicy Bypass -File scripts\check_tasks.ps1

설정마다 한 줄씩 OK 또는 FAIL이 나오고, 마지막 줄이 OK all checks passed이면 됩니다. FAIL이 하나라도 있으면 종료 코드가 1입니다. -NoWake로 등록했으면 점검에도 -NoWake를 붙입니다.

check_tasks.ps1이 보는 값 (요약)
대상기대 값
두 작업 공통배터리에서 시작·계속(DisallowStartIfOnBatteries, StopIfGoingOnBatteries = False), MultipleInstances = IgnoreNew, 로그온 방식 Interactive, 실행 파일이 venv의 pythonw.exe
my-planner인자 -m my_planner, ExecutionTimeLimit = PT0S, 재시작 999회·1분 간격, 작업 폴더 = 저장소 루트, 트리거 3개(로그온 1, 절전 복귀 이벤트 Power-Troubleshooter ID 1, 5분 반복 시간 트리거), State is Running
my-planner-wake인자 -c pass, WakeToRun = True, 트리거가 지금 config.toml로 계산한 시각과 같음
아직 노트북에서 돌려 보지 않은 스크립트두 PowerShell 스크립트는 클라우드에서 만들고 XML 템플릿만 자동 테스트했습니다. 처음 실행할 때 오류가 나면 출력 전체를 GitHub 이슈 #16에 남겨 주세요(토큰은 출력되지 않습니다). 테스트 결과서 미결 항목 참고.

  • “오늘”은 논리적 날짜입니다. 하루는 새벽 04:00에 바뀌므로 새벽 0시~3시 59분은 전날로 칩니다.
  • 비서가 먼저 보내는 메시지는 하루 최대 3회입니다. 고정 안내(로그인·한도 등)는 세지 않습니다.
  • 그 밖의 기본값: 두뇌 호출 하루 60회, 그냥 대화는 30분 안에 이어 말하면 같은 대화, 계획 모드는 마지막 메시지 뒤 2시간이면 닫힘, 비서가 제안한 초안은 3일 뒤 정리, 한 번에 넘기는 글은 8000자까지, 두뇌 호출 한 번은 300초(5분)까지(brain_timeout_s).
  • 시각을 바꾸려면 config.toml의 [schedule.*]를 고칩니다. 설정은 비서가 시작할 때 읽으므로 Stop-ScheduledTask -TaskName my-planner로 멈춘 뒤 등록 스크립트를 다시 실행합니다(스크립트가 깨우기 시각을 다시 계산하고 작업을 시작합니다). 주간 회고 요일은 일요일만 됩니다.

텔레그램 명령 (bot/commands.py)
명령하는 일비서의 답 (원문)

/help명령 안내위 명령 목록과 그 밖에는 그냥 말씀해 주세요. 할 일 추가, 옮기기, 완료, 우선순위 정하기를 도와 드려요.

명령 뒤에 @봇이름이 붙어도 됩니다. 명령과 그 답도 원문 기록에 남습니다.

문구는 Dahun 확인 필요위 명령 답과 아래 버튼 알림 문구(✓ 확정: 제목, ✗ 뺐어요: 제목, 이미 정리된 할 일이에요., 컨디션 N 기록했어요.)는 스펙이 정하지 않아 구현 중에 만든 것입니다. 스펙 v4 부록 A에 모여 있고 Dahun이 확인하기 전까지 바뀔 수 있습니다.

6백업에서 복구하기

README의 절차 그대로입니다. PowerShell에서 저장소 폴더(E:\my-planner)로 가서 순서대로 합니다.

  1. 작업을 멈춥니다5분 워치독이 다시 띄우지 않도록 끄고 멈춥니다(콘솔에서 실행 중이면 Ctrl+C). 
    Disable-ScheduledTask -TaskName my-planner
Stop-ScheduledTask -TaskName my-planner
  2. 백업을 제자리에 복사합니다지금 DB는 지우지 않고 옆으로 옮겨 둔 뒤, 가장 최근 백업을 state\planner.db로 복사합니다. 파일 이름의 날짜는 state\backups\에서 가장 최근 것으로 바꿉니다. 옛 DB의 WAL 파일이 남아 있으면 지웁니다. 다시 시작해도 같은 알림이 오면 하루 앞 백업으로 다시 해 봅니다. 
    Move-Item state\planner.db state\planner.db.broken -Force
Remove-Item state\planner.db-wal, state\planner.db-shm -ErrorAction SilentlyContinue
Copy-Item state\backups\planner-2026-10-23.db state\planner.db
  3. 알림 표식을 지웁니다다음에 또 문제가 생기면 다시 알리게 됩니다. 
    Remove-Item state\integrity_notice_sent -ErrorAction SilentlyContinue
  4. 다시 시작합니다 
    Enable-ScheduledTask -TaskName my-planner
Start-ScheduledTask -TaskName my-planner
복구하면 잃는 것백업 날짜 뒤에 나눈 대화는 data\transcripts\에 남아 있지만, 그 사이에 바뀐 할 일과 컨디션은 백업 시점으로 돌아갑니다.

7안전 모드

시작할 때 DB를 PRAGMA quick_check로 검사합니다. DB가 손상됐을 때만 비서는 스스로 고치지 않고 기다립니다.

어떻게 알 수 있나 텔레그램으로 한 번만 이렇게 옵니다: 데이터베이스에 문제가 있어요. 최신 백업으로 복구해야 해요. PC에서 README의 복구 절차를 따라 주세요. 그 뒤로는 메시지에 답하지 않고 정해진 연락도 하지 않습니다. 로그에는 safe_mode가 남습니다.
무엇을 하나 백업에서 복구하기의 네 단계를 그대로 합니다. 표식 파일 state\integrity_notice_sent를 지워야 다음 문제 때 다시 알림이 옵니다.
  • 안전 모드에서도 프로세스는 살아 있습니다. 그래야 작업 스케줄러가 계속 다시 띄우지 않습니다.
  • 알림 전송이 실패하면 표식을 만들지 않고, 다음 시작 때 다시 보냅니다.
  • 안전 모드에 들어가는 경우는 둘뿐입니다: quick_check 결과가 ok가 아니거나, OperationalError가 아닌 DatabaseError(“file is not a database” 등)가 났을 때입니다. 로그에는 db_integrity_failed 또는 db_corrupt가 먼저 남습니다.
  • 디스크 I/O, 파일 잠금, 열기 오류(OperationalError)는 손상으로 보지 않습니다. 안전 모드로 가지 않고 프로세스가 0이 아닌 종료 코드로 끝나며(로그 fatal_error), 워치독이 5분 안에 다시 띄웁니다. 멀쩡한 DB를 백업으로 덮지 않기 위해서입니다. 계속 반복되면 로그의 fatal_error를 확인합니다.

전원 상태별 동작

AC 전원, 절전확인됨회차 5분 전에 깨어납니다(S4 성공)
배터리, 절전꺼져 있음전원 옵션의 배터리 “절전 모드 해제 타이머 허용”이 “사용 안 함”이라 깨우지 못합니다. 다음에 켜질 때 따라잡기로 보냅니다

  • 이 노트북은 전통적인 S3 대기입니다(Modern Standby 아님). 절전 중에는 네트워크가 끊기고 프로세스가 멈춥니다. 깨어나면 따라잡기가 놓친 회차를 한계 안이면 보내고, 지났으면 건너뜁니다.

  • 깨어나면 비서가 텔레그램 연결을 다시 시작합니다(직전 tick과 3분 넘게 차이 나면). 로그에 resume_detected, polling_restarted가 남습니다.
  • 두뇌가 생각하고 메시지를 보내는 동안에는 비서가 절전을 막고, 끝나면 풉니다.
  • 배터리에서도 깨우려면: 제어판 > 전원 옵션 > 설정 변경 > 고급 전원 관리 옵션 변경 > 절전 > 절전 모드 해제 타이머 허용 > 배터리 사용을 “사용”으로 바꿉니다. 비서는 이 설정을 바꾸지 않습니다.
  • 프로세스가 죽으면 “실패 시 재시작” 설정이 아니라 5분 워치독 트리거가 다시 띄웁니다(S6). 최악의 경우 5분 뒤입니다.
  • 텔레그램은 받아 가지 않은 메시지를 24시간까지만 보관합니다. PC가 24시간 넘게 꺼져 있었다면 그동안 보낸 메시지는 사라질 수 있습니다.
  • 노트북이 잠든 동안 보낸 답도 보낸 시각으로 판단해, 그 시각에 답하던 회차 대화로 이어집니다(예: 03:00에 보낸 저녁 체크인 답을 09:30에 받아도 저녁 대화).

답하는 도중 꺼지면

  • 받은 메시지는 답하기 전에 DB(inbound_pending)에 가린 글로 먼저 저장합니다. 답하는 도중 PC가 꺼지거나 로그오프해도 다음에 켜질 때 그 메시지에 답합니다. 할 일 변경은 두 번 되지 않습니다.
  • 드물게 같은 답이 두 번 올 수 있습니다(보낸 직후, 처리 완료를 적기 전에 꺼진 경우). 메시지를 받은 직후 몇 밀리초 안에 꺼지면 그 메시지는 사라질 수 있습니다.
  • 다시 처리해도 답하지 못한 메시지는 세 번까지 다시 해 보고, 그다음에는 버리고 로그에 inbound_dropped만 남깁니다.
  • 답을 텔레그램으로 보낼 때는 바로 3번(1초, 2초 간격)까지 해 봅니다. 그래도 안 되면 그 답은 다음에 프로그램이 시작될 때 보냅니다(로그 message_send_failed). 그 전에는 다시 보내지 않으므로 늦게 도착할 수 있습니다.
  • 한 번의 생각(두뇌 호출)이 300초를 넘으면 멈추고 오류로 봅니다. 할 일을 아직 바꾸지 않았을 때만 다시 해 봅니다. 깨어난 직후 연결이 반쯤 끊겨 비서 전체가 멈추는 일을 막습니다.

  2. 데이터 보관 여부 정하기필요하면 data\와 state\backups\를 외장 디스크에 복사해 둡니다. 저장소 폴더 E:\my-planner를 지우면 할 일, 원문 기록, 백업이 모두 사라집니다.
  3. 세션 사본 지우기 (선택)%USERPROFILE%\.claude\projects\에서 my-planner 관련 하위 폴더를 지웁니다.
  4. 토큰 무효로 하기 (선택)봇을 다시 쓰지 않을 거라면 BotFather에서 /revoke로 토큰을 바꿔 옛 토큰을 쓸 수 없게 합니다.
